1　研究背景与动机

大模型办公助手正在快速普及，但企业与机构在涉密文档（合同、薪酬、病历、客户资料）处理上面临一个根本矛盾：数据越敏感，越需要 AI 的能力，却也越不能把数据交出去。无论是调用云端 API，还是把对话写入本地日志、向量库与审计文件，每一个跨越本地边界的环节都可能成为泄露面。

现有的通用做法存在结构性缺陷。"提示用户不要粘贴敏感信息"依赖人的自觉而不可靠；"整体关闭联网"则牺牲了云端强模型的能力。二者都没有把隐私保护变成系统本身的属性。我们的出发点是：把隐私保护从"使用约定"下沉为"架构约束"——让大模型在物理上"看不见"敏感数据，却依然能把活干完。这既保留了可用性，又从机制上消除了泄露面。

围绕这一目标，我们把办公智能体的泄露面归纳为四类，并逐一设计防线：

出网面

敏感明文随 prompt 发往云端，离开本地即失控 → 脱敏网关。

落盘面

会话记录、向量库、摘要把真实隐私写进磁盘 → 加密映射 + 入库即脱敏。

留痕面

审计日志本为追溯，却可能反成二次泄露源 → 审计只存脱敏预览。

执行面

智能体具备写盘/删除/执行能力，被诱导即造成物理破坏 → 沙箱 + 白名单 + 熔断审批。

2　关键挑战

把上述目标做成一个可用的系统，需跨越四道核心挑战：

其一，可用性与不可见性的张力。若把敏感值简单删除，模型会因上下文断裂而无法作答。必须在"抹去真实值"与"保留语义结构"之间取得平衡——这正是我们采用占位符化而非删除的设计动机：占位符保留实体类型与位置信息，使模型仍能理解"这里有一个手机号"并据此组织回答。

其二，识别的召回与精确难以两全。中文办公文本里，手机号、身份证、银行卡、人名、金额形态多变（全角、分段、国际前缀、单位混排），既要高召回不漏，又不能误伤订单号、版本号、日期等业务数字。我们以"正则粗筛 + 程序化精验"两段式应对。

其三，防护必须贯穿全链路，而非只在入口。脱敏若只做在用户输入，落盘的会话、审计、向量库、以及模型输出的还原环节仍会泄露；任一环节旁路，整体即失效。这要求把同一套脱敏管线强制施加到所有数据出入口。

其四，可证明性。"隐私有效"不能靠宣称，需要在明确的威胁模型下、以可复现的攻击实验来度量。这驱动我们设计了第 5 节的攻防评测。

3　系统概览与架构

系统采用「GUI 层 — 推理引擎层 — 安全内核层」三层解耦。安全内核由隐私引擎、策略引擎、密钥管理、审计日志四个独立模块组成，可脱离 GUI 单独测试与评测。数据在系统内的旅程为：

用户输入 $x$ ⟶ 脱敏 $\hat{x}$ ⟶ ReAct 推理 / 工具调用 ⟶ 结果脱敏 ⟶ 还原 $D(\hat{y})$ ⟶ 呈现用户

其中模型侧全程只接触 $\hat{x}$ 与占位符化的工具返回；每一环节的事件均同步写入哈希链审计。算力支持本地 Ollama（数据不出网）与 OpenAI 兼容云端（出网内容已脱敏）双模式。

3.1　内核不可插件化，其余皆可插（V3.4 新增）

把能力做成插件，是"让系统长大"的常规做法；但对安全产品，它同时是最危险的改造——一旦脱敏豁免、命令白名单、审批放行、审计写入这些判定权可以被第三方代码接管，"安全"本身就不再由我们掌握。因此我们把边界画在能力性质上，而不是画在模块归属上：

层内容是否可插件化
安全内核脱敏网关、策略白名单、审批放行、审计哈希链、沙箱文件工具、模型接入❌ 永不开放（判定权不可外包）
能力扩展补充识别敏感实体、扩展附件解析、工作流模板、导出格式、审批决策提示✅ 开放，且只能"做加法"
表 2-1　内核 / 插件的边界（按能力性质划分，而非按模块归属）

"只能做加法"不是口号，而是逐条落在代码里的可验证约束：

  • 识别只增不减：插件通过 register_extra_recognizer 追加命中区间，内核会复核每一条（越界 / 超长 / 跨行 / 重叠 / 超量丢弃），实体类型强制加 PLUGIN_ 前缀；内核不存在"让某段内容免于脱敏"的入口——插件写坏了最坏结果是"这条没生效"，不会造成泄露，也不可能造成豁免。
  • 模板不降审批：插件贡献的工作流模板由内核注册，高危步骤（写盘 / 删除 / 执行命令 / 导出文件）一律强制人工审批，插件声明 auto 也会被纠正并在界面标注"审批由内核强制"；模板 id 不得覆盖内核模板，未知工具整条拒绝。
  • 内核兜底不可顶替：导出格式名（json/html/md/docx）为内核保留，插件占用即拒；附件解析只在"内核本来不支持的格式"上优先，内核原生格式（PDF/Word/Excel/文本/音频）始终以内核为准。
  • 能力跟着开关走：每次启停插件都重算能力集合（注销模板、摘除识别器），审计详情记录注册/注销明细——"界面显示已停用、实际还在生效"在架构上不允许出现。
  • 不允许静默失效：钩子函数名与钩子名不一致时不再静默跳过，而是记为错误；界面提供插件自检逐个确认声明的钩子都有同名实现；配置文件读不出来必须告警（识别类插件的静默失效等于"以为在保护、实际没保护"）。

工程实现上，内核只暴露两个"只增不减"的扩展点（core/privacy_engine.py 的追加识别器注册表、core/workflow.py 的外部模板注册），其余能力（解析优先级、导出分发、能力同步）由服务层编排，yindun/core/ 不认识插件。插件契约集中在 yindun/plugins/host.py：钩子清单、载荷净化、禁用能力黑名单、依赖门禁、超时隔离。随包内置 7 个插件（自定义敏感词表 / 扩展附件解析 / 办公工作流模板包 / 导出格式扩展 / 审批决策提示 / laya 风险分级 / 操作意图预判），全部默认关闭、按需启用。

4　隐私保护机制

4.1　脱敏算法的形式化定义

设文本全集为 $\mathcal{X}$，敏感实体识别器 $\mathcal{E}:\mathcal{X}\to 2^{\mathcal{X}}$ 输出文本中的敏感实体集合。隐私网关定义为一个随机化映射：

$$A_k:\ \mathcal{X}\ \longrightarrow\ \hat{\mathcal{X}}\times\mathcal{M},\qquad A_k(x)=\big(\hat{x},\;M\big),\quad M=\{\,p_i \mapsto \mathrm{Enc}_k(e_i)\,\}_{e_i\in\mathcal{E}(x)}$$

其中 $\hat{x}$ 是将每个实体 $e_i$ 替换为占位符 $p_i$ 后的文本（送入模型），$M$ 为映射表，真实值以密钥 $k$ 下的 Fernet 密文存储。占位符形如 $p_i=[\,\mathsf{Type}_i\_\,i\_\,r_i\,]$，$r_i\leftarrow\{a\text{–}z,0\text{–}9\}^4$ 为随机 nonce。还原算子 $D_k$ 将输出中的占位符解回明文：

$$D_k(\hat{y},M)=\hat{y}\!\!\prod_{p_i\in M}\!\!\big[\,p_i \leftarrow \mathrm{Dec}_k(M[p_i])\,\big]$$
先把两条性质分开（V3.4.6）：本系统的效果由性质不同的两条主张构成，报告与演示中都不得合并成一个数字。
① 网关机密性（架构保证）：对任何已被识别出的实体，其明文出现在出网文本中的概率为 0——这是占位符替换 + 位置化替换 + 加密映射的直接后果，不依赖语料，也不随识别覆盖率变化。
② 识别覆盖率（经验测量）：真实文档中的敏感值有多少能被识别器认出来。它必然受限于规则覆盖的形态与评测语料，任何确定性规则系统都不可能对未知形态给出保证，本工作报告的是实测值而非承诺值（见第 5 节留出集与未覆盖形态清单）。
如果只报告②的一个漂亮数字（例如"召回 100%"），实际上是把①的架构保证错误地读成了全系统的覆盖率——这是本报告在 V3.4.6 中专门修正的表述缺陷。

在既定威胁模型下，系统主张以下四条性质（均针对已被识别的实体集 $\mathcal{E}(x)$）：

  • 机密性（Confidentiality）：对任意 $e\in\mathcal{E}(x)$，$\Pr\big[e \subseteq \hat{x}\big]=0$——模型侧无明文（实验 5.3.1 实测出网明文实例 $0$）。注意该性质的量词落在 $\mathcal{E}(x)$ 上：它保证的是"识别出的不看、没识别的不保证"，因此必须与识别覆盖率联合阅读。
  • 可逆性（Recoverability）：$D_k(A_k(x))=x$（实验 5.3.3 实测往返逐字一致 $60/60$，另在真实格式文档评测中复验 8 种格式）。
  • 还原不可伪造（Unforgeability）：攻击者在不掌握 $M$ 时构造命中他人映射的字面量，成功概率受 nonce 空间约束 $\Pr[\text{collide}]\le 36^{-4}\approx 5.9\times10^{-7}$（实验 5.3.4 劫持 $0/500$）。
  • 持久化机密（Persistence-Confidentiality）：无密钥 $k$ 时，磁盘产物 $\hat{x},\,M,\,\text{Audit},\,\text{Vector}$ 均不可恢复明文（实验 5.3.6–5.3.8 命中 $0$）。
性质边界（诚实声明）：本机制是确定性脱敏而非差分隐私，不主张对"未被规则覆盖的实体类型"或"可由背景知识重识别的属性组合"提供保证；人名识别依赖上下文触发词，无触发词的连续人名列举可能漏检；算法精验（Luhn / 校验位）会主动放过非法格式数字，属"宁漏不误伤"的既定取舍。
第二轮红队另发现并已修复两类实现层缺陷（不属机制边界）：替换未按命中位置定位导致同串错位漏脱敏、人名窗口会把字段标签首字吞入（如"张伟电"）；修复后回归复测：正样本泄露 0、负样本误伤 0（阈值 0）。
执行沙箱边界（V3.4.5 更新）：命令执行是策略层控制（白名单 + 子命令级收口 + 脚本 realpath 沙箱归属校验 + 子进程环境收敛 + 人工审批 + 审计）叠加进程容器（Windows Job Object：句柄即杀——应用退出/超时即终止整棵进程树，进程数上限 64），并可选严格模式直接禁用解释器（仅留只读命令）；仍不是 OS 级隔离——被放行的 .py 脚本以当前用户权限运行，理论上仍可触达沙箱外资源；需要更强隔离时应配合系统级方案（受限账户/虚拟机）。
可还原性缺陷（V3.4.5 修复，属实现层）：真实格式文档评测发现——anonymize 的后续规则运行在"已含占位符"的文本上，可能命中占位符内部或跨越其边界（如 ADDRESS 分支把 [BANKCARD_0_xxxx]订单号 尾段当地址），产生交叉替换使真实值无法还原；现已把占位符改为对后续规则不透明（仅在非占位符片段上匹配），并修复银行卡尾部吞换行，回归断言"脱敏→还原逐字一致"（随机 nonce 采样）。
评测口径边界（V3.4.6 取代 V3.4.4 表述）：本报告不主张任何形式的"全覆盖 / 零遗漏 / 召回率达标"。识别覆盖率一律给出分母（如 222/280）与语料规模，并同时公开未覆盖形态清单；"泄露 0 / 劫持 0 / 持久化命中 0"这类读数的量词一律落在已被识别的实体上，与识别覆盖率无关。本系统的效果陈述不构成对真实文档环境的普适安全保证。

4.2　识别与精验流水线

识别采用两段式：正则 $R_e$ 负责召回，程序化校验器 $V_e$ 负责精确，实体 $e$ 被判定为敏感当且仅当 $e\in R_e \wedge V_e(e)$。校验器针对不同实体类型实例化：手机号归一化后须恰为 11 位、银行卡须过 Luhn、身份证须过 GB11643 校验位（可选）、15 位证须命中地区码或触发词、人名须"姓氏表 ∩ 角色触发词窗口"。覆盖 20+ 类实体并按 GB/T 35273 思想做三级数据分级。

4.3　密钥体系

映射表真实值经 Fernet（AES-128-CBC + HMAC-SHA256）加密：$\mathrm{Enc}_k(\cdot)$。主密钥 $k$ 由密钥管理器统一托管，Windows 下经 DPAPI 按当前用户账户包裹：$k_{\text{stored}}=\mathrm{DPAPI}_{\text{user}}(k)$，磁盘仅存 $k_{\text{stored}}$，密钥文件移出项目目录并收紧 ACL。由此将"能否解密"归约为"是否为该 Windows 登录用户"，构成持久化机密性的信任根。

4.4　威胁模型与攻击博弈

我们按攻击者能力定义四类对手，并以博弈方式刻画安全性。记脱敏-还原系统为 $\Pi=(A_k,D_k)$，敏感实体集 $\mathcal{E}(x)$。

对手能力对应防线
黑盒仅观察出网文本 $\hat{x}$ 与模型输出（被攻破的模型服务方、链路窃听者）机密性：$\hat{x}$ 无明文，注入亦无法泄露未掌握数据
黑盒·主动可向待处理文档植入内容（伪造占位符、注入越权指令）还原不可伪造（nonce）；指令不改变"模型看不到明文"
白盒读取本地磁盘持久化文件（会话/审计/映射/向量库），但不在活动用户会话内持久化机密：真实值密文存储，无 $k$ 不可解
白盒·持钥劫持当前 Windows 用户会话、可调用 DPAPI 取回 $k$超出防护目标：等价"用户本人"，是安全与可恢复性的既定边界

以出网泄露博弈为例：$\mathsf{Exp}^{\text{leak}}_{\Pi}(\mathcal{D})$ 中，对手从语料 $\mathcal{D}$ 取 $x$，观察 $\hat{x}=A_k(x)$，输出一个猜测值 $e^*$；若 $e^*\in\mathcal{E}(x)$ 则对手胜。机密性等价于 $\Pr[\mathsf{Exp}^{\text{leak}}\Rightarrow 1]=0$。还原劫持博弈 $\mathsf{Exp}^{\text{hijack}}$ 中，对手植入字面量占位符 $p^*$ 诱导 $D_k$ 将他人明文写入其可控输出，成功概率受 nonce 空间界定。

5　攻击实验与结果

5.1　评测协议：开发集 / 留出集分离（V3.4.6 重做）

复赛评审指出"评测基于规模有限的合成样本，结论不宜泛化"。这条意见指出的不是一个数字错误，而是方法论缺陷：若在用于调参的那份语料上报告召回率，得到的数字必然偏乐观。因此本版把评测拆成两套语料、两种角色，脚本与结果 JSON 均随仓库提供，可一键复现：

语料规模角色与纪律
开发集
tests/privacy_eval.py		13 篇合成办公文本 / 41 个敏感实体 / 17 个业务数字负样本规则设计与调参所用。只作为回归基线（锁定既有行为不回退），不得用作精度声明。
留出集
tests/privacy_holdout_eval.py		60 篇随机化生成文档 / 280 个注入敏感值 / 80 个负样本由固定种子确定性生成，注入值与开发集零重合（脚本内置自检）；规则冻结后一次性运行，数值如实记录。

6　纵深防御与审计

隐私之外，智能体的物理副作用同样需要约束。系统对每个具备副作用的工具叠加多层防线，并以哈希链审计全程留痕。

路径沙箱（可读写范围）

目标路径先 realpath 化解符号链接 / junction，再以 commonpath 判定是否落在可读写范围内（范围可以是多个根，逐一比对）；文件名强制 basename，杜绝 ../ 穿越；写盘前对最终落点二次校验，拦截指向外部的链接跟随。范围是「默认可读写范围」且可在设置里改（V3.6.7 起可直接指到桌面或资料目录；V3.6.8 起默认范围 = 程序目录 + 用户桌面 / 文档 / 下载，按系统外壳的真实路径解析以兼容 OneDrive 重定向——这三个目录是人天天动的地方，把它们判成"越界"等于让智能体什么都做不了）：范围内的操作按权限档走；范围外按档位判定（计划拒绝 / 变更前确认逐次审批且弹窗显示完整真实路径 / 自主与完全访问放行），并且一律写进审计、工具结果里明写「本次操作在可读写范围之外：<路径>」——不做静默放行。系统目录与凭据/密钥类路径是与档位无关的硬地板（deny / confirm），放行权只属于宿主策略层（模型自带的"允许越界"参数一律丢弃）。文件管理族（移动 / 复制 / 重命名 / 批量改后缀 / 新建目录）与读写工具同受这套判定：两端路径都判、目标已存在时默认拒绝覆盖、批量改名先整批预检（撞车即整批拒绝，不做一半）。

熔断审批

策略引擎（deny-by-default）判定的高危操作挂起后台线程；弹窗展示申请工具、目标路径与即将执行的命令 / 即将写入的内容（可滚动核对），人工授权才放行，超时自动驳回。

命令白名单

命令名限 $\{$python, pip, git, echo$\}$，shlex 拆为 argv 后以 shell=False 执行。参数级拦 shell 操作符与绝对系统路径；子命令级只留只读入口——python 仅能执行沙箱内 .py（-c/-m/标准输入一律拒绝），pip/git 仅只读子命令，git 另拦 -c/--git-dir/--upload-pack。运行时：脚本 realpath 归属校验、子进程环境收敛（剥离密钥与内部变量）、审批弹窗展示脚本预览；执行置于 Windows Job Object 进程容器（句柄即杀、超时终止整棵进程树、进程数上限 64），可切换严格模式直接禁用解释器。属策略层 + 进程容器，非完整 OS 级沙箱。

链锚点

链式哈希只能证明"中间没被改"，防不住两种攻击：降级改写（抹掉"无 HMAC"标记后用无密钥 sha256 重算整链）与尾部截断。为此增设一枚 HMAC 锚点，固定"条数 + 链头 + 历史 legacy 前缀长度"，并放在密钥旁的用户目录——与密钥同一个理由：不能与它保护的对象同盘，否则删掉锚点即重新不可发现。规则：legacy 只允许出现在锚定前缀内、条数不得少于锚点、链头必须一致；锚点缺失而链非空判无效，需用户显式"重建锚点"。残余局限：能改写用户目录的攻击者（≈本机已被完全控制）仍可连锚点一起重做——纯本地审计挡不住这一层，故如实声明。

哈希链审计

每条日志哈希 $h_i=\mathrm{HMAC}_\kappa(h_{i-1}\,\|\, ext{entry}_i)$，篡改即校验失败；审计自身落盘前统一复用脱敏管线掩码，只存脱敏预览（见 5.2.7）。

模式级防线

快速模式禁用一切写操作（只读安全）；思考模式开放完整工具调用，推理深度 1–10 级可调。高危操作只在思考模式下存在，且始终经熔断审批。

实测：执行白名单外的 tasklist 触发拦截，模型如实说明"系统未能执行该命令"，全程无命令执行副作用。

脱敏 RAG 知识库

机密文档"入库即逐块脱敏"，向量库只存占位符。实机演示（外部算力 GLM-4.7）：对已入库的《合同_隐盾项目.txt》提问，系统经 search_knowledge_base 检索后以占位符形态送云作答（出网内容已脱敏），回答再由输出层在本机还原——模型全程只见占位符。回归：test_kb_pipeline / test_e2e_local（含"检索工具被真实调用"断言）。已知边界：外部模型若自行改写占位符编号，该片段会以占位符原样显示。

入库顺序：必须先整篇脱敏、再切块——顺序颠倒时，长于单块（500 字符）的实体（PEM 私钥、长连接串）会被切碎成明文碎片入库。每块只保留本块用到的映射，跨块还原不串值；向量库元数据只留文件名。

9　结论与展望

隐盾把"让大模型安全地处理涉密办公数据"从使用约定下沉为架构约束：以内存级脱敏网关关闭出网与落盘泄露面，以沙箱/白名单/熔断审批约束物理副作用，以哈希链审计实现可追溯且自身不泄露。效果陈述按两条性质分开：网关机密性是架构保证（对已识别实体：出网明文 0、还原劫持 0/500、白盒持久化与审计命中 0、往返逐字一致 60/60），识别覆盖率是经验测量（留出集 222/280，其中声明支持写法 222/230，并公开 50 例未覆盖形态清单）——本报告不作任何覆盖率承诺，效果读数一律带分母与限定。核心问题均以 git 提交与回归测试留痕，形成"发现—修复—验证"的工程闭环；本轮留出集自身也复现了这一闭环：发现三类实现盲区（JSON 引号键、括号注释人名、19 位卡号）→ 修复 → 换种子复测。V3.5.0 把系统从桌面单机推向企业部署形态（§9.1）：控制面只汇总掩码内容与元数据、只能用"收紧"的方式下发策略、并以外部锚定补强审计链的尾部删改检测——集中管理的能力是加上去的，前面各节的性质一个都没减。V3.6.13 进一步把判定从"操作是否合规"推进到"用途是否合规"：确定性用途闸门在模型与工具之前拒绝"收集个人信息用于出售/牟利"，把"外发个人信息"的红色警示放到审批弹窗最上方，并公开知识库检索的适用范围与"检索结果是片段、不是全文"的边界——安全产品不能只回答"这一步能不能做"，还要先回答"这件事该不该做"

同一约束也决定了扩展方式（V3.4）：判定权留在内核、能力开放给插件，插件只能扩大保护范围或增加可用性，不能缩小保护范围——这让系统可以持续长大，而"安全"不随扩展而稀释。

9.1　企业部署形态：控制面（V3.5.0）

单机形态回答不了企业最常问的一句话——"两百台机器怎么管"。控制面（`yindun/control/`）把这个问题接住， 但它的设计不是"再加一个服务器"，而是让集中管理不去破坏前面七节建立的性质。三条边界写死在代码里：

① 控制面架构上拿不到明文

它看到的内容等于端点本地审计落盘的内容，一个字不多——审计在落盘前已统一掩码（§5.3.7），上报前还会再过一遍脱敏管线做纵深防御；映射表真实值由 Fernet 加密、主密钥经 DPAPI 绑定端点当前 Windows 用户，因此即便控制面拿到映射表也解不开。控制面的数据边界是"掩码内容 + 元数据"，不是"原始数据"：敏感路径在这边只以 [SENSITIVE_PATH_0_xxxx] 形态出现，模型提示词与回答从不经过控制面。

② 策略只能收紧，不能放行

可下发项仅四类：敏感路径（并集）、审批下限（取更严）、允许的模型与插件（交集）、强制严格模式（或）。脱敏豁免、审批放行、白名单放行、审计开关没有任何下发通路——键白名单与"降级键"检测会整包拒绝（anonymize/bypass/auto_approve/whitelist…），端点侧还有单调合并兜底。因此有一个可检验的结论：控制面被完全攻破，它能做到的极限也只是"让端点管得更严"，放行不了任何一次脱敏豁免或审批跳过。这与 §3.1"判定权不可外包"是同一个决策。

③ 审计链头外部锚定

§6 承认过一条残余局限：能改写用户目录的攻击者可以连本地锚点一起重做。控制面逐次保存 (条数, 链头, legacy 前缀) 的时间序列，把"本地可重写"的证据变成"远端只增不改"的证据——尾部截断、同长度改写、中间缺口、批内断链、legacy 前缀变短、端点自报锚点不可信，六种手法都会被检出。同时如实声明边界：服务端没有 HMAC 密钥也不该有，所以它证明的是"自首次锚定起链自洽且未被删改"，不能验证 HMAC 真伪，也覆盖不到首次上报之前的历史；端点失联只呈现"最后上报时间"，不等于安全。

④ 默认关闭、本机留痕、不做整机监控

端点上报默认不启用（"数据不出网"是本产品的立身之本，集中管理必须是显式选用，绝不静默上报）；每次上报成功/失败都写入本地审计（control_report 事件），用户有权知道"什么离开了这台机器"；覆盖范围仅限隐盾自己经手的文件与命令事件，不是系统级 DLP，也不做模型流量代理——用量只上报计数与体量。

实现与验证：HTTP 服务与存储全部使用 Python 标准库（SQLite + http.server），不新增任何依赖，单文件 exe 交付形态不受影响；core/ 除新增一个审计事件类型外零改动。控制台与主产品同源设计语言（灰阶 + 单一强调色 + 等宽数据），五页：态势总览 / 事件台账 / 端点资产 / 策略下发 / 模型用量。tests/test_control_plane.py 七组用例锁住上述性质（六种删改手法、降级键与单调不变式、令牌只存哈希、出网不泄明文、并发读 12 线程 × 6 轮）。原型边界如实声明：默认只监听回环、单一管理令牌、无多租户 RBAC、无 TLS、无速率限制、端点侧尚无定时上报调度器、策略尚未接到内核策略引擎——要对外提供服务必须补齐这些前提，我们不把原型说成产品。

下一步

  • 收掉留出集暴露的在册缺口：补复姓姓氏表（成本极低）；并把"每次识别规则变更即换种子重跑留出集"固化为发布前流程；
  • 引入轻量中文 NER补充规则式识别——5.4 节清单中最大的一块（表格单元格人名、顿号列举、无触发词人名）都源于"人名依赖触发词窗口"，这正是 NER 的用武之地；
  • 补齐汉字大写金额识别；点/斜杠分隔符变体须先解决与 IPv4 地址的歧义（归一化后长度冲突），否则"多拦"会变成"误伤"；
