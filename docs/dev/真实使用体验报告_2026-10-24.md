### 10:42 · 任务 1：让它盘点「工作资料」文件夹（模型：2b · 快速）

- **我做的**：直接打字「帮我看看我桌面上「工作资料」文件夹里都有哪些文件，分类给我列一下」回车
- **过程感受**：
  - ✅ 发送立刻有等待动画，工具执行过程能看到（"列出目录文件"），不抓瞎
  - ⚠️ 第一轮工具跑去列了**程序目录 E:\yindun-agent**（跟我的问题毫无关系），浪费约 28 秒
  - ⏱ 总耗时 71 秒——这还叫"快速"模式，本地 2b 确实慢
- **结果**：给了 Markdown 分类汇总，但**答非所问**——我要「工作资料」文件夹，它把**整个桌面 60+ 个文件**全列出来了（连我桌面上的游戏 mod、个人表格都在里面），根本没进「工作资料」子文件夹
- **定性**：模型能力问题为主（2b），但"第一轮列沙箱目录"这个弯路更像产品路径提示没做好

### 10:45 · 任务 1 追问：纠正它（模型：2b · 快速）

- **我做的**：「不对，我说的是桌面上那个叫「工作资料」的文件夹，不是整个桌面。你进到那个文件夹里，把里面的文件列出来」
- **结果**（77 秒）：它再次去列了 `C:\Users\Andy\Desktop`，然后在回答里**声称"已读取「工作资料」文件夹内容"**，标题都写着「📁工作资料文件夹文件列表（共约 60+ 个）」——实际上把整个桌面当成了工作资料
- **感受**：
  - ❌ 最不能忍的一条：**它 confidently 说了一个错误前提**。作为员工我如果不点开看，会以为"工作资料里有 60 个文件"
  - ✅ 好的一面：工具行折叠条里写着真实路径 `C:\Users\Andy\Desktop`，细心能发现穿帮；落库加密我也读不了明文（安全设计确实在起作用）
- **定性**：模型幻觉（2b 上限）为主；但"工具行显示真实路径 vs 回答声称另一个路径"这种矛盾，产品其实可以做个一致性校验

### 10:47 · 换模型：去设置页接 GLM-4.7f（公网档）

2b 这个理解力干不了复杂活，正好负责人给了我一个公网 API。以真实用户身份走一遍"设置 → 模型接入 → 公网"的配置流程，顺便看看这流程顺不顺。

### 10:50 · 配置公网模型（智谱 GLM）：一半顺畅一半卡死

- **顺畅的部分** ✅：
  - 设置页默认就落在"模型接入"，三档（本机/局域网/公网）分得清楚，每档都标注数据去向
  - 填显示名称 + Base URL + API Key，点「测试连接」**一次通过**，还自动列出 11 个可用模型
  - 保存供应商成功，密钥栏变成"已配置（留空则沿用已存密钥）"——不回显，符合预期
- **卡死的部分** ❌ **BUG-1（高优先级）**：
  - 「＋ 添加模型」填 glm-4.7f → 点「保存模型」→ **"保存失败：未知原因"**，反复重试一样
  - 换成「编辑」已有条目 glm-4.5 改成 glm-4.7f → 一样报"保存失败：未知原因"
  - 键盘逐字输入（不是粘贴）也一样——**公网档的模型条目根本存不进去/改不了**
  - 而且报错就叫"未知原因"，不告诉用户任何线索，只能干瞪眼
- **临时绕过**：只能用测试连接时带出来的 glm-4.5 凑合用（能力够，但我想用的 4.7f 加不进去）
- **定性**：产品 bug，与模型无关

### 10:55 · 快速模式的"写拦截"体验（意外收获 + 被卡死）

- **我做的**：直接在快速模式下发「把会议纪要移到新建子文件夹」
- **结果**：1 秒内被前置拦截，回复说清了三件事——当前是快速模式、写操作被禁用、请切到「思考」再发（还预告会弹审批）✅ 说明清晰，不冤枉用户
- **但是**：它让我切的「思考」按钮，我连点了 4~5 次**毫无反应**（同在顶栏的明暗切换一点就灵）。普通用户到这里就死锁了：快速不让写、思考切不过去。后来不知道哪次点进去生效了（怀疑跟顶栏拖动区域吞 mousedown 有关，时好时坏）
- **定性**：产品提示做得好，但「思考」切换按钮点击可靠性存疑（BUG-2，需真人复验）

### 11:00 · 重发任务：撞上 GLM 限流

- 切到思考模式重发 → 智谱返回 OpenAIRateLimitError（请求过于频繁）
- ✅ 错误提示合格：一句人话（"请等待片刻后再发送"）+ 原始错误码都给了，没有糊弄
- ⚠️ 小坑：免费/低档 API 有 RPM 限制，连续对话容易撞；但这是 API 侧的事，不算产品问题

### 11:02 · 第一个真实审批弹窗 + 第一个"差点被坑"（2b · 思考模式）

- **流程走通了**：思考模式下它先做文件搜索/列目录（工具行有真实路径和耗时），然后弹出审批弹窗
  "隐盾安全决策网关拦截"，展示申请工具（新建目录）、目标路径、完整工具参数 JSON——**不是盲签** ✅
- **差点被坑**：它要在 `E:\yindun-agent\工作资料\会议纪要` 建文件夹——这是它自己拼的路径！
  我的文件明明在 `C:\Users\Andy\Desktop\工作资料`。更要命的是弹窗里"目标路径"写着
  `C:\Users\Andy\Desktop`、参数里却是 E 盘路径，**两处信息打架**，普通用户根本不知道哪个是真的 ❌
- **我点了"驳回拦截"**：它没有偷偷重试，继续推理后如实收尾："连续 2 轮都没有成功结果，已经停止重试"，
  还列出可能原因（越界判定/能力不足/参数不可用）和建议（改可读写范围/问得更具体/换更大模型）✅
  这个失败体验是诚实的，比假成功好得多。但整个思考轮耗时 266 秒，2b 真的很磨人
- **学到的**：不把绝对路径说清楚，2b 就会用"沙箱根+自己拼"的路径来碰运气；弹窗的"目标路径"与
  参数 JSON 不一致是产品该修的展示问题（BUG-3）

### 11:06-11:14 · 文件整理任务反复受挫：2b 干不了，GLM 限流卡脖子

- **2b（思考模式）**：给了绝对路径后它把**整句提示词当路径参数**传给工具（工具行能看到整句话被当成目录名），
  连续两轮失败后如实放弃。结论：2b 干不了多步骤文件整理，这是模型上限，不算产品问题
- **glm-4.5**：第一轮工具执行是对的（扫描了 C:\Users\Andy\Desktop\工作资料），但下一轮推理就撞
  OpenAIRateLimitError——这个 key 的 RPM 很紧，每轮推理之间要等很久。**高强度员工的最痛体验**：
  不是"不会做"，而是"做到一半断粮"。等 90 秒再试（API 侧问题）
- **顺带的好评**：等待期间注意到工具行每次都显示真实路径+耗时，出问题时能看出"它到底干了什么"，
  这比一堆黑盒强

### 11:15 · BUG-1 根因补充 + 负责人纠偏（目标模型应是 glm-4.7f）

- 负责人指出我该接的是 **glm-4.7f**（免费档限流更松），4.5 是测试连接时自动带出来的
- 但「添加/编辑模型」表单保存永远报"保存失败：未知原因"——翻了下前端代码，后端校验失败会返回
  具体错误文案（如"名称、模型 ID、接口地址都不能为空"），而"未知原因"意味着 **js_api 调用本身
  没拿到响应**（桥接层异常被吞）。这是真 bug，不是我的操作问题
- 为了继续测试，我用产品自己的配置层（SettingsStore）把 glm-4.7f 写进自定义模型（等价于替用户
  绕过坏掉的 UI），并如实记录：**普通用户到这里就被 BUG-1 卡死了**

### 11:29-11:44 · 文件整理任务终于跑通（2b · 思考模式 · 每步审批）

- **新建文件夹** ✅：给全路径后一次成功。审批弹窗路径与参数一致（之前"打架"是 2b 给错路径，弹窗本身没毛病）。
  授权后它还主动做了列目录验证。但总结跑偏：跑去搜"1009.txt 内容"然后说"未找到"——**活干对了、话没说对**
- **移动 5 个文件**：过程很挣扎——第一次它幻觉出带空格的文件名"会议纪要 1009.txt"（弹窗里被我抓到、驳回）；
  给单个文件的简单指令后成功，然后它自己接着逐个申请移动剩下 4 个，我逐个授权（每次审批都要点一次，
  安全是对的，但 5 个文件点 5 次弹窗，员工会觉得繁琐——希望能有"本次会话内信任此目录"的选项）
- **假失败比假成功更坑**：一轮实际移了 4 个文件（磁盘验证属实），总结却说"已移动 1 项"——
  用户会以为没移完又去重复操作。工具真值校验保证了实际操作全对，但**模型总结可以和工具事实相反**，
  产品应该把总结锚定在工具结果上
- **最终成绩**：5 个文件全部移入「会议纪要」子文件夹 ✅（磁盘验证），整个任务从 11:02 折腾到 11:44，
  约 40 分钟——2b 的能力上限 + 每轮思考 100~260 秒的等待，是"高强度提效"的反面

## 总结评价（一个高强度用 AI 的普通员工的心里话）

### 会不会继续用？

**安全相关的设计我服气，但以现在这个速度，日常提效我会犹豫。**

具体说：
1. **让我放心的部分**（这是我会推荐给同事的唯一理由）：删文件、移文件每次都弹审批、写完审计；
   粘贴客户隐私信息时有绿色提示条告诉我"识别到什么、换了什么"；会话落盘是加密的（我自己想翻都翻不到明文）。
   作为要经手患者名单和合同的人，这些"看得见的防线"比一句"我们很安全"值钱得多。
2. **让我崩溃的部分**：**慢**。本机 2b 思考模式一轮 100~350 秒是常态；一个"移 5 个文件"的活
   折腾了 40 分钟（其中一大半在等模型）。公网 GLM 又被 API 限流卡死（每分钟几次就断粮）。
   高强度提效的前提是"快"，目前两头都不占。
3. **让我骂娘的 bug**（按痛感排序）：
   - **BUG-1**：公网模型"添加/编辑模型"保存永远报"保存失败：未知原因"——想用更好的模型加不进去
   - **BUG-2**：顶栏「快速/思考」切换鼠标点不动（复现 9 次，仅 1 次成功），键盘 Tab+Enter 才可靠；
     而快速模式又拦截写操作，等于"功能开关被卡住"
   - **BUG-3（体验）**：模型总结可以和工具事实相反——实际移了 4 个文件，它说"已移动 1 项"；
     活干对了、报告错了，比假成功更坑
   - **BUG-4（体验）**：回答里会冒出"隐私说明"把 [PHONE_x_y] 占位符、落盘掩码这类**产品内部概念**
     甩给用户；还幻觉出不存在的文件名
   - **小槽点**：审批弹窗每个文件都要点一次（批量 5 个点 5 次），希望有"本会话信任此目录"；
     顶栏部分按钮点击不可靠（审计黑匣子、右栏折叠、新建对话都遇到过点不动）

### 给开发同学的话

- **最该修的一个**：BUG-1/BUG-2 都指向"点击/保存这类基础交互不可靠"，安全产品输在"按钮点不动"上太冤了
- **最值钱的一个设计**：删除前置审批（秒弹）和隐私隔离网关的实时提示条——建议答辩时重点演示这两个
- **性能坦白话**：2b 模型撑不起"高强度使用"的宣传，要么换 7b+ 模型做默认推荐，要么把界面定位改成
  "轻量安全沙盒"；GLM 免费档限流也不是产品能控制的，文档里该写清楚
