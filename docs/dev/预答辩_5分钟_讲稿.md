## 第 3 页 · 二、主要功能与预期目标

**kicker**：二、主要功能与预期目标
**标题**：五个功能，四个目标：可用、不可见、可审计、可部署
**页面元素**：上半区 5 个功能卡片；下半区 4 个目标标签。

**功能**

1. **脱敏对话**：27 类敏感实体在内存中替换为占位符，模型全程只见占位符，回答本机还原。
2. **文件与办公工具**：15 个工具覆盖列目录、读写、移动、复制、改名、批量改后缀、建目录；默认可读写范围＝程序目录 + 桌面/文档/下载。
3. **脱敏知识库**：入库即逐块脱敏，向量库只存占位符，检索结果标注“片段不是全文”。
4. **安全审计**：HMAC-SHA256 哈希链 + 外部锚点，可一键校验、导出。
5. **企业控制面**：只汇总掩码事件与元数据，策略只能收紧，端点上报默认关闭。

**预期目标**

- **可用**：本机 4B 模型即可跑，不需要 GPU。
- **不可见**：对已识别实体，出网明文 0 例（架构保证）。
- **可审计**：每次工具调用 / 审批 / 还原都有链上记录。
- **可部署**：两个免安装 exe，双击即用。

**演讲词（55 秒）**

> 功能有五块：第一，脱敏对话，27 类实体在内存里换成占位符；第二，15 个文件与办公工具，覆盖整理、移动、批量改名；第三，脱敏知识库，入库就脱敏，向量库零明文；第四，安全审计，哈希链加外部锚点；第五，企业控制面，只上报掩码事件，策略只能收紧。预期目标四个：可用——本机 4B、不需要 GPU；不可见——对已识别实体，出网明文 0 例；可审计——每次操作留痕；可部署——两个免安装 exe。

## 第 4 页 · 三、设计方案及技术实现（一）

**kicker**：三、设计方案及技术实现
**标题**：三层解耦 + 内存级脱敏网关 + 四道防线
**页面元素**：上方一张三层架构图；下方三段式数据流；右侧四道防线标签。

**架构**

```
UI 层（pywebview / WebView2）
        ↓ 事件总线
服务层（AgentService / 工具编排 / 审批）
        ↓
安全内核（core/ · 零 Qt）——脱敏 / 权限 / 审计 / 沙箱
```

**内存级脱敏网关**

- 三段式：`anonymize → invoke → deanonymize`，真值只在进程内存中出现。
- 映射表 Fernet 加密，主密钥 Windows DPAPI 保护；占位符带 nonce，防字面量劫持。
- 识别：正则粗筛 + 程序化精验，覆盖 27 类实体。

**四道防线**

- 沙箱：默认可读写范围 + realpath 双重校验，符号链接逃逸拦截。
- 白名单：命令去 shell 化，python 仅限沙箱内脚本，进程容器执行。
- 审批：高危操作熔断挂起，弹窗展示真实路径与待写入内容。
- 审计：HMAC 链 + 链锚点，篡改/尾部截断可被发现。

**数字口径（带分母，不写 100%）**

> 留出集 60 篇 / 280 个注入值：完整脱敏 **264 个**，未覆盖 **16 个**（94.3%）。这是修复后在原留出集上的**复测值**，规则冻结首跑是 222/280——两个数都留档，不拿复测数冒充泛化能力。未覆盖形态清单公开；对已识别实体，出网明文 **0 例**。

**演讲词（55 秒）**

> 设计上是三层解耦：UI 用 pywebview，服务层做工具编排和审批，安全内核在 core 里、零 Qt、可以独立测试。核心是内存级脱敏网关：anonymize、invoke、deanonymize 三段式，真值只在进程内存里出现；映射表 Fernet 加密，主密钥 DPAPI 保护。再往外是四道防线：沙箱、命令白名单、熔断审批、哈希链审计。数字我们不写 100%：留出集 60 篇、280 个注入值，当前复测完整脱敏 264 个，未覆盖 16 个，94.3%；首跑是 222/280，修复后的数含修复收益，我们不把它说成真实分布；对已经识别出来的实体，出网明文 0 例。

## 第 5 页 · 三、设计方案及技术实现（二）

**kicker**：三、设计方案及技术实现
**标题**：laya 三级分级 + 插件只做加法：安全能力可扩展，判定权不外包
**页面元素**：左右分栏。

**左：laya 三级风险分级（数据边界由近及远）**

```
本机 laya 决策模型  →  局域网 laya 服务  →  正则规则
  数据不出机器          出机器不出企业        全离线
```

- 每级都写明**本次来源**，绝不冒充“模型结论”。
- 模型不可用 / 权重未下载 / 推理失败 → 自动回落正则，并在界面标注。
- **只做建议，不参与放行**：高风险只影响弹窗提示，放行仍由人工审批。

**右：插件体系——“只做加法”的五条硬约束**

- 7 个内置插件：自定义敏感词 / 扩展附件解析 / 工作流模板 / 导出格式 / 审批决策提示 / **操作意图预判** / **laya 风险分级**。
- 插件只能**多识别、多解析、多导出、多模板**；`approve / mask / bypass / whitelist / write_audit` 等判定类能力**永久禁止**。
- 载荷净化、超时隔离、内核兜底、启停即收回。
- **一句话**：插件是“能力插座”，不是“权限后门”。

**演讲词（60 秒）**

> 这一页讲两个技术实现。左边是 laya 风险分级：按数据边界分三级——本机 laya 模型、局域网服务、正则规则；每一级都写明本次来源，模型不可用就自动回落，但**只做建议、不参与放行**。右边是插件体系：7 个内置插件，可以多识别一类实体、多解析一种格式、多一种导出；但插件永远拿不到判定权——审批、脱敏豁免、白名单、审计写入，这些钩子在宿主里是永久禁止的。也就是说，能力可以扩展，安全边界不外包。

### 现场审计校验 · 操作卡（11 秒）

**界面位置**：左侧栏底部的盾牌图标，tooltip 是「审计黑匣子」（`#btn-audit`）。右侧是被折叠的「审计」面板。

1. **先确认右侧面板是收起的**（如果已经展开，点面板右上角的「收起面板」）。这一步是为了让“打开→出现校验结果”有明确的视觉变化。
2. **点左侧盾牌图标「审计黑匣子」**。右侧「审计」面板展开，同时前端会重新调用一次 `audit_snapshot`，后端重新校验 HMAC 链与锚点。
3. **指给评委看链徽标**：`✔ 哈希链完整性通过（HMAC-SHA256 + 链锚点）`。下面一行是链详情（条数 / 锚点状态 / 最近校验）。
4. **想再校验一次**：点顶部「审计」tab，或收起面板后再点一次盾牌图标。每次打开都会重新校验，不是缓存的旧结果。
5. **如果校验失败**：面板顶部会出现红色横幅「审计链校验未通过：<原因>」；只有“锚点缺失 / 目录迁移”这类可执行原因才会出现「重建锚点（接受当前链）」按钮。现场**不要点重建**，只念原因即可。

> 口播：“打开审计面板这个动作本身就会重新校验一次，不是缓存的旧结果。徽标写的是哈希链完整性通过，下面能看到条数和锚点状态。”

**彩排检查**：提前点一次，确认徽标是绿色的「完整性通过」；如果显示红字，先不要演示篡改，按报告里的原因处理或换一台干净的演示机。

### B4 · 插件体系（展开稿）

- **7 个内置插件**：`custom_dict`（自定义敏感词）、`doc_extra`（邮件/网页解析）、`office_wf`（工作流模板）、`export_pack`（导出格式）、`decision_hint`（审批决策提示）、`intent_guard`（操作意图预判）、`laya_risk`（风险分级）。
- **钩子清单**（`yindun/plugins/host.py` 唯一来源）：
  - `advisory_for_approval`：只产出给人看的提示，不进入执行/安全路径；
  - `recognizer`：只扩大识别范围，不能让任何内容免于脱敏；
  - `attachment_parser`：多解析一种格式，产出文本仍走同一条脱敏管线；
  - `workflow_template`：模板里的高危步骤由内核强制人工审批；
  - `export_renderer`：多一种导出格式，内核格式始终保留兜底。
- **永久禁止**：`approve / allow / deny / mask / unmask / bypass / skip_privacy / whitelist / write_audit / set_permission`。
- **工程保障**：manifest 校验、依赖门禁、超时隔离（硬上限）、载荷净化（限长/限宽/强制前缀）、启停即同步能力、自检能发现“函数缺失/依赖缺失”。
- **一句话**：插件是“能力插座”，不是“权限后门”。

| 档位 | 数据边界 | 不可用时 |
|---|---|---|
| 本机 laya 模型 | 数据不出这台电脑 | 自动回落局域网（若配置）→ 正则 |
| 局域网 laya 服务 | 出机器、不出企业内网 | 自动回落正则 |
| 正则规则 | 全离线 | 规则文件为空会如实说“未给出结论”，不编“安全” |

- 提示里写明**本次来源**（本机模型 / 局域网 / 正则），绝不冒充。
- 本机实测：删除类 高危、读取类 低危、命令执行 中危；模型对命令行破坏性动作判别有限时，提示会主动说明。
- laya 只影响提示，不参与放行；高风险仍需人工审批。

### B11 · 操作意图预判 + 用途红线（展开稿）

- **内核用途闸门**（确定性，不依赖模型）：收集/整理个人信息 + 出售/转卖/变现 → **模型与工具之前直接拒绝**；+ 外发/公开 → 本机可整理，审批弹窗顶部红色警示。
- **插件“操作意图预判”**：先答“想干什么”（意图 / 数据 / 去向 / 用途），再让“是否相符”“操作风险”两条建议发言；模型只能加重、不能减轻。
- **三层不再自相矛盾**：用途触线时，`decision_hint` 不再说“相符”，`laya_risk` 标注“只评操作本身”。
- 误伤规避：「买进卖出 / 买卖记录 / 外卖」不误判；「把客户资料拿去交易」「买卖这些客户名单」会拒绝。

### B12 · 上下文预算与长回答（展开稿）

- 本机 Ollama：`/api/show` 探测真实窗口（qwen3.5:2b 实测 262144），按本机 `num_ctx` 上限折算 32768；云端按声明/家族估值（未知 16384）。
- 历史占 35%、附件 25%、输出预留后封顶 8192；8k 模型不会被硬塞 8k 输出。
- 长回答命中单次上限：自动续写一次 → 仍超就请模型重写“不超上限的精炼版” → 才提示「回复继续」。
- 关键实现：`num_ctx/num_predict` 必须是 `ChatOllama` 的**顶层字段**（放在 `options` 里会被忽略）。

## 3 分钟评审答辩：分工与标准答法

**分工**：A（隐私/算法）、B（工程/产品）、C（场景/合作）。每人不抢答，回答控制在 25–30 秒；评委可随时打断，**先给结论**。
**结构**：结论 → 一个证据 → 一句边界。

| # | 问题 | 谁来答 | 标准答法 |
|---|---|---|---|
| 1 | 和 DLP / 数据防泄漏有什么区别？ | A | DLP 管边界和审计，我们管“模型看得见什么”；DLP 不能让你放心用大模型，我们能，二者互补。 |
| 2 | 识别漏了怎么办？ | A | 两条性质分开：已识别的出网明文 0 例；未识别形态公开清单，留出集 94.3%（修复后复测，首跑 222/280），不吹 100%。 |
| 3 | 小模型能力够吗？ | A | 4B 实测能完成常见办公任务；空回复有兜底和重试，关键任务可切云端或更大模型。 |
| 4 | 安全怎么自证？ | B | 红队评测 + 500 轮定向劫持未成功 + 60 篇真实格式文档往返一致；但都限定在我们构造的攻击面/语料内，不是泛化保证。哈希链加外部锚点，可以现场校验。 |
| 5 | 商业模式 / 怎么落地？ | C | 客户端私有化部署，企业控制面订阅，行业插件定制；先做律所和医疗，本机 4B 不需要 GPU。 |
| 6 | 团队做了什么？ | C | 连续独立测试报告逐条复核：用途红线、写意图、知识库、续写、窗口、审批超时等都已修复并回归，重建 exe 发版——能持续交付，不只是做了个原型。 |
| 7 | 能现场跑一遍模型吗？ | B | 可以，但一段长回答要几十秒，5 分钟里不划算；现场可以先演不依赖模型的审计校验和权限切换，模型推理答辩后单独跑。 |
| 8 | 控制面上生产还差什么？ | B | RBAC、TLS、多租户、高可用；我们把它标成演示级原型，不把原型说成产品。 |
| 9 | **laya 是什么？为什么用它？** | A | 一个本地风险分级模型：按数据边界分本机 / 局域网 / 正则三级，模型不可用自动回落并写明来源；它只做建议，不参与放行。 |
| 10 | **插件会不会破坏安全？** | B | 插件只有“建议型/增强型”钩子，判定类能力永久禁止；载荷净化、超时隔离、内核兜底、启停即收回，四道约束都在回归里。 |
| 11 | **你们和其他 agent 插件有什么区别？** | B | 大多数插件扩展“能做什么”；我们的插件连“能不能放行”的接口都没有——能力可以加，安全边界不外包。 |
| 12 | **为什么审批建议一会儿“相符”一会儿“低危”？** | A | 已经修了：现在先判用途，再判相符，最后判操作风险；用途触线时前两条不会给出“相符/低危”的背书。 |
| 13 | **长回答为什么总截断？** | B | 根因是 `num_ctx/num_predict` 放错位置、直答路径没看长度元数据；现在按模型定窗口，续写 + 精炼重答，实测已触发。 |

**三句绝对不说**：
1. “召回 100%”
2. “绝对安全”
3. “控制面是成熟产品”
