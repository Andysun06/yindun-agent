## 第 2 页 · 大模型进涉密办公，卡在“可用”与“不可见”

**标题**：数据越敏感，越需要 AI；却越不能把数据交出去
**页面元素**：四个泄露面卡片——出网面 / 落盘面 / 留痕面 / 执行面，每张卡片一句人话。
**画面建议**：中间放一张“企业办公数据流”示意，四个红点标在四个泄露位置。

**演讲词（30 秒）**

> 企业想把大模型用在合同、薪酬、病历、客户资料上，但数据只要出了本机就失控：出网面、落盘面、留痕面、执行面，每一个环节都是泄露面。要么牺牲能力，要么牺牲安全——这是我们想解决的根本矛盾。

**注意点**
- 这一页只讲“为什么难”，不要提前讲方案。
- 四个面各 6~7 秒，语速平稳，不要逐个展开技术细节。

## 第 3 页 · 核心思路：模型全程只见加密占位符

**标题**：真实值进模型前变成占位符，回答回来在本机还原
**页面元素**：一张数据流图
`用户输入 → 脱敏（27 类实体）→ 模型只见 [NAME_0_x] → 回答 → 本机还原 → 用户看到真值`
图下方一行：映射表 Fernet 加密 · 主密钥 DPAPI 保护。

**演讲词（35 秒）**

> 我们的做法是：数据进模型前，在内存里替换成加密占位符；模型全程只看到占位符；回答回来，在本机还原成真值。映射表用 Fernet 加密，主密钥由 Windows DPAPI 保护——磁盘上拿到映射表也解不开。识别用“正则粗筛 + 程序化精验”，覆盖 27 类实体。

**注意点**
- 只讲这一张图，不要展开正则和实体清单。
- 强调“内存中替换”：不是先落盘再脱敏，减少评委对“临时文件泄露”的追问。

## 第 5 页 · 可验证：两条性质必须分开说

**标题**：不说“召回 100%”：识别覆盖率是经验值，机密性是架构保证
**页面元素**：左右两块大数字

| 识别覆盖率（经验值） | 机密性（架构保证） |
|---|---|
| 在册形态 **264/264** | 已识别实体出网明文 **0** |
| 全量口径 **264/280（94.3%）** | 500 轮还原劫持 **0** 成功 |
| 负样本 **80/80 零误伤** | 往返逐字一致 **60/60** |

底部一行小字：未覆盖形态清单公开，不掩盖。

**演讲词（45 秒）**

> 我们不说“召回百分之百”。识别覆盖率是经验值：留出集在册形态 264 比 264，全量 264 比 280，负样本 80 比 80 零误伤。但机密性是架构保证：已经识别出来的实体，出网明文 0；500 轮还原劫持 0 成功；往返逐字一致 60 比 60。没识别出来的形态我们公开清单，不掩盖。这两条性质必须分开说。

**注意点**
- 这是全场最容易被记住的一页，**不要赶**，45 秒给足。
- 数字要大，来源写在页脚（留出集 60 篇 / 280 注入值 / 规则冻结后一次性运行）。
- 千万别说“100% 召回”“绝对安全”。

## 第 6 页 · 真产品 + 企业控制面

**标题**：不是课堂 demo：两个 exe、39 套回归、控制面只能收紧
**页面元素**：左右分栏
- 左：交付形态
  - 客户端 exe：双击即用
  - 控制端 exe：双击开控制台
  - **39 个测试/评测套件全绿**；CI Windows/Ubuntu × Python 3.11/3.13
  - 打包后校验“exe 内资产 = 源码”
- 右：企业控制面
  - 架构上拿不到明文
  - 策略只能收紧：敏感路径并集 / 审批下限取更严 / 模型与插件取交集
  - 审计链头外部锚定
  - 端点上报默认关闭

**演讲词（60 秒）**

> 这不是课堂 demo。交付是两个免安装 exe：客户端双击即用，控制端双击开控制台。39 个测试和评测套件全绿，CI 跑 Windows 和 Ubuntu 双平台，打包后还会校验 exe 内资产等于源码。企业侧有控制面：它架构上拿不到明文，看到的等于端点审计落盘的内容；策略只能收紧——敏感路径取并集、审批下限取更严、允许模型和插件取交集。控制面被攻破，也只能让端点管得更严。

**注意点**
- 30 秒讲产品完成度，30 秒讲控制面；不要念测试套件清单。
- 如果评委偏学术，把“控制面”换成“可复现构建 + 评测方法”，备用页里有展开。
- 别说“控制面是成熟产品”，后面第 7 页要主动说边界。

## 3 分钟答辩：分工与标准答法

**分工**：A（隐私/算法）、B（工程/产品）、C（场景/合作）。每人不抢答，回答控制在 25–30 秒。
**结构**：结论 → 一个证据 → 一句边界。

| # | 问题 | 谁来答 | 标准答法 |
|---|---|---|---|
| 1 | 和 DLP / 数据防泄漏有什么区别？ | A | DLP 管边界和审计，我们管“模型看得见什么”；DLP 不能让你放心用大模型，我们能，二者互补。 |
| 2 | 识别漏了怎么办？ | A | 两条性质分开：已识别的 0 出网；未识别形态公开清单，覆盖率 94.3%，不吹 100%。 |
| 3 | 小模型能力够吗？ | A | 4B 实测能完成常见办公任务；空回复有兜底和重试，关键任务可切云端或更大模型。 |
| 4 | 安全怎么自证？ | B | 红队评测、500 轮劫持 0 成功、60/60 往返一致、哈希链加外部锚点，可以现场校验。 |
| 5 | 商业模式 / 怎么落地？ | C | 客户端私有化部署，企业控制面订阅，行业插件定制；先做律所和医疗，本机 4B 不需要 GPU。 |
| 6 | 团队做了什么？ | C | 独立测试报告 12 条缺陷，我们逐条复核根因、修完回归、重建 exe 发版——能持续交付，不只是做了个原型。 |
| 7 | 能现场跑一遍模型吗？ | B | 可以，但一段长回答要几十秒，5 分钟里不划算；现场可以先演不依赖模型的审计校验和权限切换，模型推理答辩后单独跑。 |
| 8 | 控制面上生产还差什么？ | B | RBAC、TLS、多租户、高可用；我们把它标成演示级原型，不把原型说成产品。 |

**三句绝对不说**：
1. “召回 100%”
2. “绝对安全”
3. “控制面是成熟产品”
