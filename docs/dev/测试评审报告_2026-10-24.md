## 二、创新性：21 / 25

### 加分依据
- **核心思路有辨识度**："让大模型看不见敏感数据却依然能干活"——内存级占位符网关 + 可逆还原，并把同一条脱敏管线强制施加到输入、落盘、RAG、审计所有出入口。区别于"提示用户别粘贴敏感信息"与"整体断网"两类现有做法，也区别于纯本地化方案（后者牺牲云端强模型能力）。
- **评测方法论是真创新**（技术报告 §5）：把"网关机密性（架构保证）"与"识别覆盖率（经验测量）"两条性质分开陈述；开发集/留出集分离、规则冻结后一次性运行、"发现→修复→换种子重跑"纪律、公开 16 例未覆盖形态清单。该纪律在同类竞赛作品中罕见，且复跑可验证（见上）。
- **机制设计有巧思**：插件 `FORBIDDEN_HOOKS`（判定权永不外包）+"只能做加法"；控制面策略"只收紧"（控制面被攻破也只能让端点更严）；审计链锚点置于密钥旁（堵降级改写与尾部截断）；宿主令牌防模型自授权越界。均为代码级可验证约束，不是口号。

### 扣分依据
- 单项技术均为成熟件：正则+Luhn/校验位精验、Fernet+DPAPI、HMAC 哈希链、Windows Job Object，无原创算法；创新在于组合与工程纪律，按"技术研发具有突破性"的标准存在上限。
- 脱敏是确定性方案而非差分隐私；人名识别依赖触发词启发式——报告已如实声明，但仍是创新高度的现实约束。

## 三、实用性：21 / 25

### 加分依据
- **"运行稳定、功能完善"经得起实测**（证据见第一节）；测试不是摆设——多个套件是历史真机事故的固化回归。
- **真实可用**：15 个文件工具（含移动/批量改后缀/撞车整批拒绝）、本地知识库脱敏 RAG、6+1 内置插件、四档权限+硬底线、全链路审计；审批弹窗实测展示完整工具参数、用途红线警示与两条插件建议，无"盲签"。
- **可用性迭代来自真实使用**：版本史大量缺陷来自负责人实测反馈（数桌面文件数不准、OneDrive 路径、Clash 代理劫持本机模型探测等），说明产品有人在真用，不是演示驱动开发。

### 扣分依据（实测发现缺陷，按严重程度）
- **D-1【主要】HEAD 上回归门禁是红的**：`tests/test_reply_feedback.py` 【7】审批超时/驳回场景 4 条断言失败，稳定复现。定位：产品侧 `_request_approval` 新增 `tool_id` 参数（`yindun/worker/agent_worker.py:229`，提交 c029231 起），该测试两个审批桩（`tests/test_reply_feedback.py:955`、`:989`）签名未跟上，桩被调用抛 `TypeError`，审批从未发生——**是测试过时而非功能回归，但当前"全量套件绿"的 README 表述不成立**，对一个以"回归纪律"为卖点的项目，这是发布流程失误。
- **D-2【中】错误归因误导**：D-1 场景中内部 `TypeError` 被包装为"⏱ 请求超时——模型服务响应太慢或网络不稳定，请检查网络连接和 VPN"，内部缺陷被报成网络问题，会带偏排障方向。
- **D-3【中】控制面是半成品**（README/SECURITY 已如实声明）：无 TLS / 无多租户 RBAC / 无速率限制 / 端点侧无定时上报调度器，策略下发尚未接入内核策略引擎——"企业管控"目前为演示级。
- **D-4【低】18 位身份证校验位默认关闭**（`privacy_engine.py:400` `IDCARD_CHECKSUM = False`）：主形态的程序化精验比宣传口径弱一档，建议改为"校验失败但形状命中仍脱敏"（宁过度不漏）。
- **D-5【低】Job Object 绑定失败静默降级**（`file_tools.py:1148-1149` `except Exception: pass`），排障缺证据。
- **D-6【低】工程卫生**：插件识别器异常用 `print` 而非 logger（`privacy_engine.py:641`）；仓库根目录 10 个未提交的 GIF 素材与 `docs/formal_assets/` 未纳管。

## 四、市场/应用潜力：18 / 25

### 加分依据
- **场景匹配真实**：涉密办公（合同/薪酬/病历）+ 个保法/GB/T 35273 合规诉求，"用 AI 但数据不出域"是政企/金融/医疗的普遍痛点；三档数据边界（本机/局域网/公网-先脱敏）与采购方合规语言直接对应。
- **可复制性有支撑**：免安装单文件 exe、零新增依赖的控制面、插件生态（含开发文档与契约测试）、CI 全量回归矩阵，横向铺开的工程基础具备。

### 扣分依据
- **护城河薄**：占位符脱敏网关思路可被大厂（Copilot+Purview、钉钉/飞书 AI、安全厂商 DLP）快速复制；本项目壁垒是工程纪律与诚实度，而非专利/数据/网络效应——"别人为什么打不过你"这个问题不好答。
- **落地形态有硬约束**：信任根是"当前 Windows 登录用户"（DPAPI）；Job Object 为 Windows 专属；确定性规则对真实分布覆盖率无保证；本地小模型的任务质量限制了对效果敏感场景的替换意愿。
- **商业化要素缺失**：无定价/部署成本/目标客户分层；控制面距"能交付给企业 IT 部门"还差一整页生产化清单（TLS、RBAC、调度器、策略接内核）。
