# 隐盾安全智能体 · 项目介绍视频脚本（HyperFrames / HTML+JS+CSS）

- **规格**：1920×1080、30fps、MP4（H.264 + AAC），目标 **4:55**（≤5:00）
- **制作方式**：HyperFrames 逐帧渲染 HTML/CSS/JS；视觉全部由 DOM + CSS 动画构成，演示素材用原始录屏/截图嵌入
- **视觉风格**：**延续《隐盾安全智能体汇报.pptx》**——白/浅绿底、`#005826` 主绿、浅绿卡片、黑体标题、细绿线；
  汇报/科研风格，克制、清楚，不做科技霓虹、粒子、3D 翻转或花哨转场
- **叙事口径**：演示为主、数据为辅；不出现“100% / 绝对安全”，统一说“对已识别实体，出网明文 0 例”
- **当前版本口径**：V3.6.20；留出集 **281/296**；30 类实体；15 个文件/办公工具；7 个内置插件；四档权限；双端交付

---

## 0. 一句话结构

**问题（4 个泄露面）→ 架构（原文不出本机）→ 四个关键动作（脱敏对话 / 审批 / 审计 / 知识库与插件）→ 证据与场景 → 收尾。**

评委看完应记住三件事：

1. 脱敏靠本地规则，不靠模型；
2. 模型只收到占位符，回答回本机还原；
3. 审批与审计是“看得见的防线”，不是口号。

## 2. HyperFrames 制作约束（按这个写代码）

### 2.0 视觉规范：和汇报 PPT 一致

视频不是宣传片，是“会动的汇报页”。所有画面按 PPT 的设计 token 走：

| 项 | 规范 |
|---|---|
| 主色 | `#005826`（深绿）；浅底 `#EEF6F1` / `#F5F9F5`；文字 `#1F2329`；次要文字 `#5B6975` |
| 背景 | 白或极浅绿；不要整屏深色/渐变/网格/粒子 |
| 字体 | 标题黑体 / 微软雅黑；正文微软雅黑；数字用 Times New Roman；不引入花体 |
| 卡片 | 圆角 6–8px、浅绿底、细绿边或左侧 3px 绿条；阴影极轻或不用 |
| 线条 | 细绿线（1px）做分组和分隔；不要发光、描边动画、霓虹 |
| 动效 | 只用 200–300ms 的 `opacity` + `translateY(8–16px)`；不做 3D 翻转、弹跳、缩放爆炸、粒子流 |
| 转场 | 淡入淡出或轻微横移；不加 whoosh 以外的音效 |
| 演示窗口 | 白底应用窗口 + 细边框，像 PPT 里放截图；不要给窗口加透视/倾斜 |
| 信息层级 | 标题 64–84px、副标题 40–48px、正文 30–36px、注释 22–26px；每屏一个结论 |

**一句话：评委应该觉得“这是那份 PPT 在放”，而不是“另一个团队做的宣传片”。**

### 2.1 舞台与时间轴

- 舞台固定 `1920×1080`，`overflow:hidden`；根容器 `position:relative`。
- 每个场景一个 `<section class="scene" data-start="..." data-duration="...">`，绝对定位铺满舞台。
- 用一个统一的 `renderAt(t)` 时间轴驱动：`requestAnimationFrame` 读当前毫秒，计算每个场景的 `enter/progress/exit`；**不要用一串 `setTimeout`**，逐帧渲染会漂移。
- 进入/退出统一用 `opacity` + `transform`（`translate/scale`），时长 200–400ms；避免 3D 翻转和大面积模糊。
- 字幕和口播分离：字幕是 DOM，口播是外部音轨；两者都按同一张时间表对齐。

### 2.2 演示素材：直接用原始 MP4，不从 GIF 反推

GIF 只是派生物，**原始 MP4 已按场景命名归档**在：

`assets/视频素材/MP4原片/`

| 原片 | 时长 | 用途 |
|---|---:|---|
| `01_脱敏对话.mp4` | 10.1s | S3 脱敏对话 |
| `02_审批放行.mp4` | 9.1s | S4 审批与删除前置 |
| `03_审计滚动.mp4` | 9.0s | S5 审计链 |
| `04_插件与扩展.mp4` | 24.1s | S6 插件页 |
| `05_脱敏知识库.mp4` | 22.1s | S6 知识库检索 |
| `06_网关占位符.mp4` | 9.7s | 创新点：占位符 |
| `07_用途红线拒绝.mp4` | 10.3s | 创新点：用途红线 |
| `08_laya决策模型.mp4` | 17.3s | 创新点：laya |

全部为 **1728×1080（16:10）**；除审计段 30fps 外均为 60fps。制作时直接从原片裁 8–12s：

1. 按场景从原片取段，`ffmpeg -ss … -t …` 裁剪；保留 1728×1080 原始尺寸，不先转 GIF；
2. HTML 用 `<video muted playsinline preload="auto">` + `currentTime` 定位；HyperFrames 逐帧渲染时用 `<canvas>` `drawImage(video)` 取帧，等 `seeked` 后再截；
3. 原片是 16:10，目标 16:9（1920×1080）：按 **100% 原尺寸**居中放置，左右各留 96px 白/极浅绿背景，像 PPT 里放应用窗口；**不要拉伸**；若确实要铺满，只裁掉上下各 5%（1080→972），注意别裁到标题栏/输入框；
4. 原片 60fps，渲染输出统一 30fps；不要在 HTML 里做变速，保持真实操作节奏；
5. 每段只保留脚本需要的 8–12s；知识库/插件原片较长（22s/24s），只取关键动作，不要整段塞进去。

> 不建议把 GIF 再放大：GIF 是 1280×800 的派生物，原片才是 1728×1080。既然有原片，就直接用原片；原片已随仓库同步（`assets/视频素材/MP4原片/`，单文件 < 100MB），组内 `git pull` 即可。

### 2.3 字体与安全区

- 字体：`Microsoft YaHei` / `Noto Sans SC`；渲染环境没有字体时，把字体文件随项目打包，用 `@font-face` 引入。
- 安全区：左右 80px、上下 60px；标题不超过两行，正文不超过三行。
- 字号：主标题 64–84px，副标题 40–48px，正文 30–36px，角标/注释 22–26px。
- 对比度：**本片以白/浅绿底为主**；深绿只用于小面积色块、标题和分隔线，不做整屏深色；浅底用深绿/深灰字，红色只给风险/失败。

### 2.4 音频与导出

- 口播：建议真人录制（或高质量 TTS），48kHz WAV；每段单独一条，按场景起点对齐；语速约 4.5 字/秒。
- 音乐：选可商用、无强旋律的轻科技底乐，音量压到口播的 -18～-22dB；转场加轻微 whoosh 即可，不要堆音效。
- 字幕：先生成 SRT，再用 DOM 烧字幕；SRT 同时作为交付附件。
- 导出：`ffmpeg -framerate 30 -i frames/%05d.png -i vo.wav -c:v libx264 -pix_fmt yuv420p -crf 18 -c:a aac -b:a 192k -movflags +faststart out.mp4`；导出后核对 1920×1080、≤5:00、音画同步。
