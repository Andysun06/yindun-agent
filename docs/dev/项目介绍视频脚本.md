# 隐盾安全智能体 · 项目介绍视频脚本（HyperFrames / HTML+JS+CSS）

- **规格**：1920×1080、30fps、MP4（H.264 + AAC），目标 **4:45**（≤5:00）
- **制作方式**：HyperFrames 逐帧渲染 HTML/CSS/JS；视觉全部由 DOM + CSS 动画构成，演示素材用视频/截图嵌入
- **叙事口径**：演示为主、数据为辅；不出现“100% / 绝对安全”，统一说“对已识别实体，出网明文 0 例”
- **当前版本口径**：V3.6.20；留出集 **268/280**；27 类实体；15 个文件/办公工具；7 个内置插件；四档权限；双端交付

---

## 0. 一句话结构

**问题（4 个泄露面）→ 架构（原文不出本机）→ 四个关键动作（脱敏对话 / 审批 / 审计 / 知识库与插件）→ 证据与场景 → 收尾。**

评委看完应记住三件事：

1. 脱敏靠本地规则，不靠模型；
2. 模型只收到占位符，回答回本机还原；
3. 审批与审计是“看得见的防线”，不是口号。

## 2. HyperFrames 制作约束（按这个写代码）

### 2.1 舞台与时间轴

- 舞台固定 `1920×1080`，`overflow:hidden`；根容器 `position:relative`。
- 每个场景一个 `<section class="scene" data-start="..." data-duration="...">`，绝对定位铺满舞台。
- 用一个统一的 `renderAt(t)` 时间轴驱动：`requestAnimationFrame` 读当前毫秒，计算每个场景的 `enter/progress/exit`；**不要用一串 `setTimeout`**，逐帧渲染会漂移。
- 进入/退出统一用 `opacity` + `transform`（`translate/scale`），时长 200–400ms；避免 3D 翻转和大面积模糊。
- 字幕和口播分离：字幕是 DOM，口播是外部音轨；两者都按同一张时间表对齐。

### 2.2 演示素材：GIF 必须转成可控帧

HyperFrames 逐帧截图时，`<img src="x.gif">` 的动画帧不保证按时间轴推进。建议：

1. 用 ffmpeg 把每段 GIF 转成 30fps MP4（`-c:v libx264 -pix_fmt yuv420p`）；
2. HTML 里放 `<video muted playsinline preload="auto">`，`currentTime = 场景内偏移`；
3. 用 `<canvas>` `drawImage(video)` 输出到舞台，或等 `seeked` 后再让 HyperFrames 截帧；
4. 每段视频只保留脚本需要的 8–12s，避免 20s+ 长片段拖慢渲染。

> 不建议把 GIF 直接放大到 1920 宽：源是 1280×800，放大 1.5× 会糊。正确做法是放在 1280×800 的“应用窗口”里，周围用深色背景和标签填充，既清晰又有产品感。

### 2.3 字体与安全区

- 字体：`Microsoft YaHei` / `Noto Sans SC`；渲染环境没有字体时，把字体文件随项目打包，用 `@font-face` 引入。
- 安全区：左右 80px、上下 60px；标题不超过两行，正文不超过三行。
- 字号：主标题 64–84px，副标题 40–48px，正文 30–36px，角标/注释 22–26px。
- 对比度：深绿底用白/浅绿字；浅底用深绿/深灰字；红色只给风险/失败，不要整屏红。

### 2.4 音频与导出

- 口播：建议真人录制（或高质量 TTS），48kHz WAV；每段单独一条，按场景起点对齐；语速约 4.5 字/秒。
- 音乐：选可商用、无强旋律的轻科技底乐，音量压到口播的 -18～-22dB；转场加轻微 whoosh 即可，不要堆音效。
- 字幕：先生成 SRT，再用 DOM 烧字幕；SRT 同时作为交付附件。
- 导出：`ffmpeg -framerate 30 -i frames/%05d.png -i vo.wav -c:v libx264 -pix_fmt yuv420p -crf 18 -c:a aac -b:a 192k -movflags +faststart out.mp4`；导出后核对 1920×1080、≤5:00、音画同步。

### 2.5 建议目录

```text
video/
├─ index.html
├─ styles.css
├─ timeline.js
├─ assets/
│  ├─ video/        # GIF 转出的 mp4（privacy/approval/audit/kb/plugins...）
│  ├─ img/          # 截图、logo、图标、告警条
│  ├─ fonts/
│  └─ audio/        # 口播分轨 + 底乐
└─ frames/          # 渲染输出
```

### 3.3 结论

**够做一支 4:30 的“演示 + 动效”项目介绍片。** 现有 8 段 GIF、审计篡改截图、控制台截图和 logo 足以覆盖核心功能；架构图、数据卡、场景卡、交付形态全部用 HTML/CSS 重画，反而比截图更清晰。

**不够做“5 分钟全实拍、全屏 1080p”的片子。** 主要差三样：口播音轨、底乐、以及 1–2 段 1080p 全屏演示（删除前置 / 控制面）。如果接受把 1280×800 的 GIF 放进应用窗口，不追求满屏，那么只补口播和底乐就能开工；如果希望演示满屏且字清楚，建议补录 3 段 1080p：脱敏对话、删除前置审批、控制台总览。

**优先级建议**：

1. 先录口播（4:45，按第 1 节逐段）；
2. 再把 8 段 GIF 转 MP4 并裁到脚本需要的 8–12s；
3. 用 HTML/CSS 做 S0–S2、S7–S9 的动效（不依赖新素材）；
4. 最后决定是否补录删除前置/控制面 1080p 片段。
