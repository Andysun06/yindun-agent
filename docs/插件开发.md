# 隐盾 · 插件开发指南

> 面向想给隐盾加能力的人。读完这份文档，你应该能写出一个可用的插件，并且清楚**哪些事插件永远做不到**——后者比前者更重要。

## 1. 设计理念：内核不可插件化，其余皆可插

隐盾把能力分成两层：

| 层 | 内容 | 能不能插件化 |
|---|---|---|
| **安全内核** | 脱敏网关、策略白名单、审批放行、审计哈希链、沙箱文件工具、模型接入 | ❌ **永不开放**。这些是"安全"本身，一旦可插拔就等于把判定权交给了任意第三方代码 |
| **能力扩展** | 补充识别敏感实体、解析新格式、导出新格式、提供工作流模板、审批决策提示 | ✅ 开放，且**只能做加法** |

"只能做加法"是硬约束，落在代码里：

- **补充识别**只能让更多内容被脱敏（范围变大＝更安全），内核没有任何"让某段内容免于脱敏"的入口；
- **工作流模板**里凡是高危步骤（写盘 / 删除 / 执行命令 / 导出文件），内核一律**强制人工审批**，插件声明 `auto` 也会被纠正；
- **导出格式**不能占用内核保留名（`json` / `html` / `md` / `docx`），内核格式始终兜底可用；
- **附件解析**不能顶替内核原生格式（PDF / Word / Excel / 文本 / 音频），只在"内核本来不支持的格式"上优先。

## 2. 插件长什么样

一个目录，两个文件：

```
<插件目录>/
├── manifest.json      # 声明：我是谁、提供什么能力、需要什么依赖
└── plugin.py          # 实现：与钩子同名的函数
```

- 内置插件放 `yindun/plugins/builtin/<id>/`
- 用户插件放 `<APP_ROOT>/plugins/<id>/`（源码运行＝仓库根目录；打包版＝exe 旁边）

**同名时用户插件覆盖内置插件**，方便本地魔改。插件只允许**本地安装**：隐盾不会联网下载任何插件代码。

## 3. manifest.json

```json
{
  "id": "my_plugin",
  "name": "我的插件",
  "version": "0.1.0",
  "description": "一句话说明（显示在设置页）",
  "author": "谁写的",
  "hooks": ["recognizer"],
  "requires": { "python": ["torch>=2.0"], "ollama_models": ["qwen2.5*"] },
  "permissions": { "network": "none", "filesystem": "read" },
  "timeout_seconds": 3,
  "provides": ["给人看的能力说明"],
  "config_files": [
    { "name": "words.txt", "label": "敏感词表", "hint": "每行一条；# 开头是注释" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 字母数字下划线，2–32 位，全局唯一 |
| `name` / `version` | ✅ | 展示名 / 语义化版本 |
| `hooks` | ✅ | 声明的钩子（见 §4），且**入口模块必须定义同名函数** |
| `requires.python` | | 需要能 `import` 的包；缺了会在界面显示"依赖未满足"并禁止启用 |
| `requires.ollama_models` | | 需要的本地模型（前缀匹配）；缺了同样禁止启用 |
| `permissions` | | 自述网络/文件权限（显示在界面徽标上，供人判断） |
| `timeout_seconds` | | 单次钩子调用的超时；仍会被该钩子的硬上限截断（见 §4 表） |
| `file_exts` | ✅（`attachment_parser`） | 负责的扩展名，如 `["eml", "html"]` |
| `export_formats` | ✅（`export_renderer`） | `{"audit": ["markdown"], "workflow": ["html_card"]}`，不得用内核保留名 |
| `format_labels` | | 导出格式的中文标签，如 `{"html_card": "卡片式 HTML"}` |
| `config_files` | | 用户可在设置页直接编辑的文本文件（相对插件数据目录，只允许简单文件名） |
| `provides` | | 纯展示用的能力说明 |

## 4. 可用钩子

| 钩子 | 类别 | 入口函数 | 硬超时上限 | 干什么 |
|---|---|---|---|---|
| `advisory_for_approval` | 建议型 | `advisory_for_approval(context)` | 120s | 在审批弹窗里给一条提示，**不参与任何判定** |
| `recognizer` | 增强型 | `recognizer(context)` | 5s | 补充识别敏感实体（只扩大脱敏范围） |
| `attachment_parser` | 增强型 | `attachment_parser(context)` | 30s | 解析内核不支持的附件格式 |
| `workflow_template` | 增强型 | `workflow_template(context)` | 10s | 提供工作流模板（高危步骤会被强制审批） |
| `export_renderer` | 增强型 | `export_renderer(context)` | 15s | 渲染导出格式 |

**永不开放的钩子名**：`approve`、`allow_operation`、`deny_operation`、`mask`、`unmask`、`skip_privacy`、`bypass`、`decide_risk`、`enforce`、`policy`、`whitelist`、`write_audit`、`sandbox_root`、`set_permission` 等。声明这些名字的插件会在加载时被拒绝，并在设置页写明原因。

超时是**每个钩子的硬上限**，不是建议值：`recognizer` 跑在脱敏内联路径上，声明 120s 也会被压到 5s——内联路径不允许拖住主流程。

## 5. 各钩子的数据契约

### 5.1 `recognizer` —— 补充识别

```python
def recognizer(context):
    """context: {"text": 原始正文}
    返回 {"spans": [{"start": 0, "end": 4, "type": "PROJECT_CODE", "level": "机密"}]}
    """
```

- `start` / `end` 是**原始正文**里的字符坐标（左闭右开）；
- `type` 会被内核强制加上 `PLUGIN_` 前缀，不会与内核实体类型（PHONE / IDCARD…）撞名；
- `level` 取 `绝密 / 机密 / 内部 / 公开`，非法值按 `机密` 处理（从严）；
- 内核会**复核每一条**：越界 / 超长（>120 字）/ 跨行 / 重叠 / 超出数量上限的一律丢弃；
- 写错了最坏结果是"这条没生效"，不会造成泄露，也不可能让内容免于脱敏。

### 5.2 `attachment_parser` —— 解析新格式

```python
def attachment_parser(context):
    """context: {"path", "ext", "name", "max_chars"}
    返回 {"text": "解析出的正文", "note": "解析说明"}；返回 None 表示不处理。
    """
```

产出文本后**照常走隐私扫描与脱敏**——插件只负责"把文件变成文本"。

### 5.3 `workflow_template` —— 提供模板

```python
def workflow_template(context):
    return {"templates": [{
        "id": "ext_my_flow", "name": "我的流程", "description": "…",
        "path_var": "project_path",          # 可选：界面填的路径写进哪个变量
        "steps": [{"name": "读文件", "tool_name": "read_local_file",
                   "tool_args": {"path": "{{project_path}}"}, "approval": "auto"}],
    }]}
```

内核侧校验（插件无法绕过）：

- `id` 不能覆盖内核模板或其它插件的模板；同一插件重复注册自己的模板视为更新；
- 每个 `tool_name` 必须是引擎已注册的执行器，否则**整条模板被拒绝**（不给用户"能跑但必然失败"的假模板）；
- 高危工具（`create_local_file` / `delete_local_file` / `modify_local_file` / `run_local_command` / `export_file`）**强制人工审批**，步骤上会标记 `forced_approval`，界面显示"审批由内核强制"。

### 5.4 `export_renderer` —— 导出格式

```python
def export_renderer(context):
    """context: {"kind": "audit"|"workflow", "format": "markdown",
                 "payload": 已脱敏的数据, "generated_at": "…"}
    返回 {"text": "渲染结果", "ext": "md", "suggested_name": "audit_report_plugin.md"}
    """
```

- `payload` 里的数据**已经脱敏**（审计条目在写入时脱敏、工作流报告在落盘前脱敏）；
- 输出落盘由内核负责：审计走审计目录、工作流报告走报告目录，文件名只取 basename——插件无法借导出写到别处；
- 格式名不能占用内核保留名，内核格式始终可用（插件停用不会让导出功能消失）。

### 5.5 `advisory_for_approval` —— 审批提示

```python
def advisory_for_approval(context):
    """context: {"tool", "args", "path", "user_request", "model", "ollama_host"}
    返回 {"level": "info"|"warn", "text": "提示内容"}；返回 None 表示不给提示。
    """
```

审批弹窗**先出现**、建议**异步补发**：慢的本地模型判断不会拖住用户做决定。建议区明确标注"仅供参考"。

## 6. 插件数据目录与可编辑配置

宿主在加载插件时会注入两个模块级变量：

```python
PLUGIN_ID = "my_plugin"          # 由宿主覆盖为真实 id
PLUGIN_DATA_DIR = "C:/…/plugins_data/my_plugin"   # 可写数据目录
```

- 用户插件的数据目录在插件自己的目录内（`<插件目录>/data/`）；
- 内置插件的数据目录在 `<APP_ROOT>/plugins_data/<id>/`——因为打包版的解包目录是只读的，写在那里重启就丢；
- `config_files` 里声明的文件可在设置页直接编辑、保存即生效，改动会写入审计（词表直接决定脱敏范围，属于安全策略的一部分）。

## 7. 调试与自检

- **设置页 → 插件自检**：逐个导入插件模块，确认每个声明的钩子都真的有同名可调用函数。
  这一步专门用来戳破"启用了却没反应"的静默失效——**钩子函数名写错不会报错，只会什么都不发生**，所以务必先自检。
- 宿主日志（控制台）会打印：超时跳过、异常、缺少同名函数、依赖未满足。
- 插件的异常与超时都被隔离，不会影响主流程与其它插件。

## 8. 安全边界（写插件前请读完）

1. 插件是**本地可执行代码**，启用即信任。隐盾只做三件事：不下载、默认关闭、启停与配置改动写审计。
2. 插件**不能**参与脱敏豁免、白名单、审批放行、审计写入——这些钩子名永不开放。
3. 插件**不能**降低审批强度：高危步骤的审批由内核强制。
4. 插件**不能**让内容免于脱敏：识别类钩子只做加法，且返回值经内核复核。
5. 插件**不能**顶替内核能力：内核原生格式与内核导出格式始终优先/兜底。
6. 插件**不能**静默失效：自检 + 日志 + 界面状态三处可见。

## 9. 一个最小可用插件（完整示例）

```
<APP_ROOT>/plugins/hello_recognizer/
├── manifest.json
└── plugin.py
```

```json
{
  "id": "hello_recognizer",
  "name": "示例：识别内部代号",
  "version": "0.1.0",
  "description": "把形如 XH-2026-001 的内部代号纳入脱敏范围。",
  "hooks": ["recognizer"],
  "timeout_seconds": 2
}
```

```python
# -*- coding: utf-8 -*-
"""示例插件：把内部代号纳入脱敏（只做加法）。"""
import re

PLUGIN_ID = "hello_recognizer"
PLUGIN_DATA_DIR = ""

_PATTERN = re.compile(r"[A-Z]{2,4}-\d{4}-\d{3}")


def recognizer(context):
    text = (context or {}).get("text") or ""
    if not text:
        return None
    spans = [{"start": m.start(), "end": m.end(), "type": "INNER_CODE", "level": "机密"}
             for m in _PATTERN.finditer(text)]
    return {"spans": spans} if spans else None
```

放进目录、重启隐盾、在设置页启用（或先点"插件自检"确认钩子被识别到），此后送模型前 `XH-2026-001` 会变成 `[PLUGIN_INNER_CODE_0_xxxx]`，模型输出里的占位符仍会由本机还原。

## 10. 相关文件

| 文件 | 作用 |
|---|---|
| `yindun/plugins/host.py` | 宿主：发现 / 校验 / 依赖检查 / 启停 / 调用 / 载荷净化 / 自检 |
| `yindun/plugins/builtin/*` | 内置插件（可作为范例阅读） |
| `yindun/core/privacy_engine.py` | 追加识别器注册表（`register_extra_recognizer`，只增不减） |
| `yindun/core/workflow.py` | 外部模板注册与内核侧安全校验（`register_external_template`） |
| `tests/test_plugins.py` | 宿主契约回归（校验 / 依赖 / 净化 / 配置 / 自检） |
| `tests/test_plugin_capabilities.py` | 能力端到端回归（识别 / 模板 / 解析 / 导出） |
