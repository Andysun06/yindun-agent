# 🛡️ 隐盾安全智能体 (Yindun Security Agent) - V3.6.17

欢迎来到 **隐盾安全智能体 (V3.6.17)** 官方代码库。

本应用是一款原生半透明悬浮智能体客户端（**默认不置顶**，需要时一键置顶并持久化）。项目经历多轮工业级深度解耦重构，视图层已整体迁移到 Web 前端（原生 ES + 设计 token，无构建步骤）。

**V3.0 重大升级**：全面迁移至 LangChain 原生 Tool Calling 协议，彻底抛弃正则解析与结构化字段提取，实现真正的 ReAct 推理循环。

**V3.3 新增**：全链路审计黑匣子、本地知识库+脱敏RAG、10类实体脱敏引擎、跨轮脱敏还原、摘要二次脱敏、工具调用对配平。

**V3.3.2 安全加固回归**：修复脱敏引擎"错位替换"导致的明文残留；命令白名单增加子命令级校验（封堵 `python -c`/`pip install`/`git -c` 等任意代码执行入口）；审批弹窗展示完整命令与待写入内容（消除"盲签"）；推理取消改为真中断；隐私回归测试泄露阈值归零。

**V3.6.17 缺陷修复批次（独立测试报告 12 条）**：核心功能与界面各半——① **用途红线双向失准**：良性「买进卖出」不再被拒，跨行「买卖 / 拿去交易 / 倒卖」不再漏判，裸「交易流水」仍判正常；② **快速模式写意图判定**：过去时追问（「什么时候被删除的」）不再误拦，「保存到桌面，可以吗」不再漏拦；③ **知识库触发信号**：弱信号遇到算法/代码/架构等通用题不再强制检索，补入报销/流水/账单/台账；④ **长文续写**：续写轮返回工具调用时不再丢弃已生成前缀，所有收尾路径统一拼接；⑤ **知识库占位符还原**：裸占位符、大小写、全角括号、连字符变体都能还原，歧义仍保留不猜；⑥ **状态行/键盘/审计栏/窗口**：状态行「思考 N/M」真正改写为「推理 N/M」，思考强度滑杆方向键可用，审计栏自动展开加载全量，最大化状态跟随系统事件、最大化不再盖任务栏、失败原因如实分档；⑦ **审批超时**停止整轮且同轮不自动重试，审批卡对知识库检索显示检索词而非项目目录。全部改动均有回归断言，测试假绿（全角状态串、只剩 1 条的审计快照）一并修正。

**V3.5.0 模型利用率与工具链（本轮）**：让智能体「不显得笨」的四件事——**省掉多余的全量生成**（已有实质答案时不再追加总结轮，少一次完整推理）、**重复调用短路**（只读工具同参数再来一次直接复用上次结果并提示别重复）、**失败反馈可行动化**（「文件不存在」会引导先列目录确认名称，而不是把裸异常丢给模型撞墙）、**工具结果真值校验**（声称写入/删除后到文件系统核对，杜绝小模型幻觉式「假成功」）；快速模式轮次 3→6，避免常见任务被硬截断。以上均有可计数断言锁定。

**V3.5.0 企业部署形态：控制面（本轮）**：单机版回答不了"两百台机器怎么管"，本轮把这个问题接住，同时**一条既有性质都没减**——① **控制面架构上拿不到明文**：它看到的内容**等于端点本地审计落盘的内容**（敏感路径已掩码，只以占位符出现），映射密钥由端点 DPAPI 托管，控制面即便拿到映射表也解不开；模型提示词与回答**从不经过控制面**。② **策略只能收紧**：可下发仅 敏感路径（并集）/ 审批下限（取更严）/ 允许模型与插件（交集）/ 强制严格模式（或）；`anonymize`/`bypass`/`auto_approve`/`whitelist`/`disable_audit` 等**降级键整包拒绝**，端点侧再做单调合并兜底——**控制面被攻破也只能让端点管得更严**。③ **审计链头外部锚定**：逐次保存 (条数, 链头, legacy 前缀)，尾部截断/同长度改写/中间缺口/批内断链等六种删改手法都会被检出（同时如实声明：服务端无 HMAC 密钥，故只证明"自首次锚定起链未被删改"，不证明 HMAC 真伪）。④ **默认关闭、本机留痕**：集中管理是显式选用的能力（绝不静默上报），每次上报成功/失败都写本地审计（`control_report`），覆盖范围仅限隐盾自己经手的文件与命令，**不是系统级 DLP**、不做模型流量代理。实现上全部使用 Python 标准库（SQLite + `http.server`，**零新增依赖**，单文件 exe 形态不受影响），`core/` 除新增一个审计事件类型外零改动；控制台与主产品同源设计语言（六页 + 明暗双主题，含统计分析）。**原型边界如实声明**：默认只听回环、无 TLS / 无多租户 RBAC / 无速率限制、端点侧尚无定时上报调度器、策略尚未接到内核策略引擎——上生产必须先补齐，不把原型说成产品。

## 🎨 核心功能特性

### 🔒 安全与隐私

1. **内存级数据隐私网关**：内置物理脱敏隔离网关（`PrivacyEngine`），覆盖 27 类敏感实体（手机号/邮箱/身份证/银行卡/IP/IPv6/MAC/金额/API密钥/JWT/私钥PEM/云平台密钥/连接串口令/口令字段/护照/车牌/统一社会信用代码/病历号/医保号/微信号/地址/敏感路径/人名等），按 GB/T 35273 思想做三级数据分级，在内存中就地执行实体模糊化与数据匿名化，并在汇报给人类时安全还原明文。识别采用"正则粗筛 + 程序化精验"（Luhn / 手机号位数 / 身份证地区码与触发词），先按精确命中区间替换再生成占位符，杜绝"同一子串在非敏感位置先出现"导致的明文残留。

2. **熔断级越界操作拦截**：当智能体企图调动物理机械臂工具并切入非默认工作区或系统核心敏感目录时，系统将强行触发独立的二次确认拦截弹窗，安全阻塞后台写盘线程，强行等待人类安全员二次审批。弹窗完整展示申请工具、目标路径与**即将执行的命令 / 即将写入的内容**（长内容可滚动），避免"看不到要执行什么就签字"的盲签风险。

3. **权限分级控制（V3.5.1 四档，V3.5.3 起每对话可单独设）**：**计划模式 / 变更前确认 / 自主模式 / 完全访问**——读取一律放行，四档的差别只在"写盘 / 删除 / 执行命令"要不要人工确认，设置页直接列出能力对照表。档位定义**只有一处**（`core/permission.py`），工具层、审批流与界面说明全部由它派生；切换后**下一个操作即按新档位判定，无需重启**。★ **沙箱是「默认可读写范围」而不是绝对墙**（V3.6.7 起，可在设置页「隐私与权限 → 可读写范围」直接改到桌面／资料目录）：**默认可读写范围 = 程序目录 + 你的桌面 / 文档 / 下载**（V3.6.8 起，注册表取真实路径以兼容 OneDrive 重定向；显式设了范围就只认它），日常整理文件不再被当成越界。范围内的操作按档位走；**范围外**的操作也按档位判定（计划拒绝 / 变更前确认逐次弹窗且显示完整真实路径 / 自主与完全访问放行），**每一次范围外操作都写进审计**、工具结果里明写路径——不做静默放行。★ 硬底线不随档位放开：**执行命令在任何档位都要人工确认**（计划模式直接拒绝），系统目录 deny 与凭据路径 confirm、脱敏网关、审计链一律照旧。

4. **全链路审计黑匣子**（V3.3 新增，V3.4.0 加固）：
   - 每轮完整记录工具调用、LLM I/O、数据流转、隐私检测/脱敏/还原全过程
   - HMAC-SHA256 哈希链式存储保证日志不可篡改，任何篡改都会被完整性校验立即发现
   - **链锚点（V3.4.0）**：哈希链只能证明"中间没被改"，防不住两种攻击——抹掉"无 HMAC"标记后重算整链的**降级改写**，以及**尾部截断**。新增一枚 HMAC 锚点（固定条数 + 链头 + 历史 legacy 前缀长度），放在**密钥旁边**（用户目录）而非审计目录内：删掉它就能让截断重新不可发现，所以不能与它保护的对象同盘。校验未通过时界面给出**人话原因**，锚点缺失可由用户显式「重建锚点」确认
   - GUI 面板提供统计概览、哈希链可视化、日志筛选，支持导出 JSON/HTML 审计报告
   - 审计只存脱敏预览，不落盘真实敏感数据，隐私安全闭环

### 🧠 智能推理架构（V3.0 核心升级）

4. **原生 Tool Calling 协议**：
   - 基于 LangChain `bind_tools()` 实现真正的工具绑定
   - 模型自主决定工具调用，无需正则解析
   - 支持 `AIMessage.tool_calls` → `ToolMessage` 完整调用链

5. **ReAct 推理循环**：
   - 推理 → 工具调用 → 观察 → 总结 的完整闭环
   - 快速模式：3 轮推理，秒级响应
   - 深度模式：可配置思考深度（1-10），最多 20 轮推理

6. **思考强度四档** *（V3.5.1 改版，原为 1–10 滑动条）*：
   - 输入框下方四档控件：**低 / 中 / 高 / 最高**（对应推理轮次 2 / 4 / 7 / 10），点一下即生效并落库
   - 动态影响最大推理轮次（depth × 2）
   - 最低思考轮数约束（max(2, depth × 0.8)），确保深度分析不过早退出

7. **即时取消响应** *（V3.1.4 新增，V3.3.2 修正语义）*：
   - 线程池包装 `llm.invoke()`，工作线程每 0.5 秒检查取消标志
   - 用户点击取消后 **约 0.3 秒内返回**（实测），并断开该轮全部信号，避免已取消那轮的中间结果污染新气泡
   - 语义边界（诚实声明）：HTTP 中的模型请求无法从外部强制打断，取消会立即释放工作线程与界面，
     在途请求在后台自然结束、结果被丢弃；取消后重发消息时两轮不会互相干扰

### 📂 文件与项目管理

8. **项目智能分析**：
   - 自动识别项目类型（Node.js / Python / Java / C# 等）
   - 递归扫描文件结构，提取关键配置文件
   - 代码文件智能采样，返回核心实现摘要
   - **强制工具调用机制**：检测到分析请求时直接执行工具，不依赖模型决策

9. **离线文档全自动挂载**：支持离线 PDF、Word (docx)、Excel (xlsx/xls)、TXT、MD、CSV 等多种机密办公文档的跨平台编码自适应提取。

10. **智能上下文记忆管理**：
    - 基于 LangChain `BaseChatMessageHistory` 标准接口实现
    - 内置 `max_tokens` 阈值（默认 5000），超出后自动触发 LLM 摘要压缩
    - 摘要保留早期对话核心信息，最近消息完整保留
    - 支持多会话隔离，会话记录持久化到 `chat_sessions.json`
    - **跨轮脱敏还原**（V3.3）：脱敏映射表跨会话持久化，历史轮次的占位符在后续对话中也能正确还原，杜绝"裸占位符"泄露给用户
    - **摘要二次脱敏**（V3.3）：摘要生成后再过一遍脱敏引擎，防止真实敏感值被复制进摘要并落盘
    - **工具调用对配平**（V3.3）：上下文裁剪时自动补全 `AIMessage(tool_calls)` ↔ `ToolMessage` 配对，避免模型收到不完整工具序列报错

### 📚 本地知识库 + 脱敏 RAG（V3.3 新增）

11. **本地知识库**：
    - 基于 Chroma 向量库 + Ollama 本地 embedding（nomic-embed-text），全程无云端依赖
    - 支持多格式文档入库（PDF/Word/Excel/TXT/MD），切块、向量化、语义检索
    - GUI 设置面板可视化管理：添加/删除文档、进度条、状态检测

12. **入库即脱敏的 RAG 管线**：
    - 文档**先整篇脱敏、再切块**，**向量库中只存占位符文本，真实隐私永不落盘**
      （V3.4.0 修正顺序：先切块会把 PEM 私钥这类长实体切碎，碎片两边都匹配不到正则，明文碎片就进了向量库）
    - 检索时全局占位符重命名 + `KB_` 前缀隔离，避免与用户输入占位符冲突；占位符类型解析覆盖含下划线/数字的实体（`MEDICAL_RECORD`/`IDCARD15`/`PRIVATE_KEY`/`ACCESS_TOKEN`/`PLUGIN_*`）
    - 向量库元数据只存文件名，不写入本机完整路径（落盘面不泄露目录结构）
    - LLM 只看到脱敏片段，接外部 API 时模型侧同样只见占位符（覆盖范围内）；回答中的占位符自动还原给用户。**口径说明**："零泄露"仅指"已覆盖实体类型 + 评测集范围内"的结果，不构成真实环境的普适安全保证——对抗集与已知边界见 tests/privacy_adversarial_test.py

### 🧩 插件体系：内核不可插件化，其余皆可插（V3.4.0 落地）

13. **为什么要这么设计**：脱敏豁免、命令白名单、审批放行、审计写入这些**判定权**一旦可插拔，等于把安全交给任意第三方代码——所以它们永不开放；而"多识别一类实体、多解析一种格式、多一种导出、多一个工作流模板"这类**只增不减**的能力，插件化能同时拿到"内核精简"与"能力可扩展"。

14. **两类钩子**：
    - **建议型**（`advisory_for_approval`）：在审批弹窗里给一条提示（如"这次操作与你刚才的请求是否相符"），只影响界面提示，不参与任何判定；建议异步补发，慢的本地模型不会拖住用户做决定
    - **增强型**（4 类）：`recognizer` 补充识别敏感实体、`attachment_parser` 扩展附件解析、`workflow_template` 提供工作流模板、`export_renderer` 渲染导出格式

15. **"只能做加法"落在代码里**：
    - 补充识别只扩大脱敏范围（内核没有任何"让内容免于脱敏"的入口），且返回区间由内核复核（越界/超长/跨行/重叠丢弃，实体类型强制加 `PLUGIN_` 前缀）
    - 工作流模板里的高危步骤（写盘/删除/执行/导出）由内核**强制人工审批**，插件声明 `auto` 也会被纠正
      （V3.6.7 起**工作流的界面入口已移除**，这条约定与内核校验仍然有效，只是用户侧暂时看不到入口）；模板不得覆盖内核模板
    - 导出格式不得占用内核保留名（`json`/`html`/`md`/`docx`），附件解析不得顶替内核原生格式——**内核兜底始终在**
    - 停用插件立刻收回它贡献的能力（模板注销、识别器摘除），"界面显示已停用、实际还在生效"不允许发生

16. **6 个内置插件**（默认关闭，按需启用；启用/停用/配置改动都写审计；**卡片直接显示运行状态**——"已触发 N 次 · 最近时间 · 正常/出错"或"等待触发"，启用了到底有没有在干活一眼可见）：
    - **自定义敏感词表**：把项目代号、内部称谓、专用术语纳入脱敏；词表可在设置页直接编辑（支持 `re:` 正则），改动立即生效
    - **扩展附件解析**：让 `.eml` / `.html` / `.mht` 也能当附件用（纯标准库，不联网），产出文本后走同一条脱敏管线
    - **办公工作流模板包**：代码安全体检（增强版）与本周工作总结，补内核模板的短板（**界面入口已于 V3.6.7 移除，能力保留**）
    - **导出格式扩展**：审计报告导出 Markdown 表格、工作流报告导出卡片式 HTML
    - **审批决策提示**：用本地模型判断"要执行的操作与你的请求是否相符"
    - **laya 风险分级**：审批弹窗补一行风险分级（高危/中危/低危），按数据边界**三级接入**——本机 laya 模型（数据不出本机）→ 局域网 laya 服务（公司内网的 OpenAI 兼容端点，出机器不出企业）→ 可编辑正则规则（全离线回退）。启用该插件后，设置栏「插件」分组里的「laya 风险分级」页配接入并「测试连接 / 试打分」，提示始终写明本次来源；只影响提示，不参与放行判定

17. **插件自检**：逐个导入插件模块，确认每个声明的钩子都真的有同名函数——专门戳破"启用了却没反应"的静默失效（钩子函数名写错不会报错，只会什么都不发生）。想自己写插件？见 [docs/插件开发.md](docs/插件开发.md)。
18. **七个插件逐个实测**（V3.5.6 起，V3.6.13 增补操作意图预判）：`tests/test_plugins_live.py` 以**插件**为单位各走一遍「启用 → 用真实入口跑一次 → 停用 → 能力收回」，并比对 **exe 内插件与源码逐文件哈希**（防「测的是源码、发的是旧 exe」）。验证边界如实标注：模型类插件的**真实推理**不在套件内（需本机 Ollama 与 laya 权重），套件用桩替身验证产品逻辑，真实链路见 `test_e2e_local.py`。本套件实测揪出并修掉一个真缺陷：`.eml`/`.mht` 不声明 charset 时中文正文会变成一片 `�`。

### 界面形态（V3.3.2 起：Web 界面，Qt 已移除）

界面是**新的 Web 界面**（pywebview + WebView2，前端 file:// 本地加载；
js_api 桥经回环随机端口 + 随机会话 UUID，实测无鉴权请求一律被拒）：

助手回答以「编号记录」呈现、输入以「指令票」呈现，并内置审计台账、知识库与插件面板。

```bash
python run.py          # 启动 Web 界面
```

> 旧的 PySide6 界面已在视图层重构完成后整体移除（`yindun/gui/` 可从 git 历史取回）。
> 界面预览（不启动后端）：浏览器打开 `yindun/app/web/index.html#mock`（`#mock-audit` 审计、
> `#mock-settings` 设置与知识库、`#mock-approval` 审批弹窗）。

### 方式一：免安装单文件 exe（推荐给使用者）

下载 `Yindun-Portable-<版本>.exe`，**双击即用**——无需安装、无需脚本。

- 配置、会话、审计日志、知识库向量数据都写在 **exe 同目录**（放桌面/便携盘均可，卸载 = 删除 exe 与同目录生成的数据）
- 主密钥由 Windows DPAPI 按当前用户保护，不随 exe 移动
- 自行构建：`python tools/packaging/build_portable.py`（产物在 `dist/`；单文件模式首次启动约需 10~20 秒解压）
- 打包不再包含 Qt（界面已改为 Web）：便携包 164MB → 127MB

**企业控制端**（管理机用，与客户端相互独立）：

```bash
python tools/packaging/build_control.py      # 产物 dist/隐盾控制端_<版本>_便携版.exe（约 19MB）
# 双击即启动集中管理服务 + 控制台；管理令牌见 exe 同目录 control_data/admin_token.txt
# 源码态等价命令：python -m yindun.control --port 8787
```

### 方式二：源码运行（仅开发调试用）

> 交付形态只有 exe：**使用者一律用上面的便携包**（免安装、免脚本）。
> 下面这条路是给改代码的人用的——**不再提供 `.bat` 启动脚本**，直接命令行即可。

```bash
pip install -r requirements.txt
python run.py                 # 启动客户端（Web 界面，pywebview）
python -m yindun.control      # 启动企业控制端
```

### 首次使用（两种方式相同）

1. **模型接入按数据边界分三档**（设置视图 → 模型接入）：**本机**（Ollama，数据不出这台电脑）、
   **局域网**（公司内网的推理服务 / Ollama，数据不出企业内网）、**公网**（云端 OpenAI 兼容接口，
   送出前内容已在本机脱敏）。每档都有独立的配置卡与「测试连接」；模型切换在输入框下方的模型胶囊里，
   按三档分组列出，换完立即生效、无需重启。详见使用说明"三、首次使用"
2. 至少下载一个模型（推荐 `qwen3.5:4b` 或其他支持 Tool Calling 的模型，如 `qwen3:4b` / `qwen2.5:7b-instruct`）
3. 启动隐盾后，本机模型会被自动检测并列出（点一下即切换）

## 🔧 技术架构

### ReAct 循环流程

```text
用户输入
    ↓
[路径检测] → 检测到分析请求 → 强制调用 analyze_project
    ↓
[隐私脱敏] → PrivacyEngine.anonymize()
    ↓
[上下文加载] → SummarizableChatHistory.get_context_messages()
    ↓
┌─────────────────────────────────────┐
│  ReAct 循环（max_rounds = depth × 2）│
│                                     │
│  ① llm.invoke(messages)            │
│     ↓                               │
│  ② 检查 tool_calls                  │
│     ├─ 有工具调用 → 执行工具 → ToolMessage
│     └─ 无工具调用 → 检查是否达到最低轮数
│         ├─ 未达到 → 强制继续分析
│         └─ 达到 → 生成总结          │
│                                     │
│  ③ 循环直到模型停止调用工具          │
│     或达到最大轮次                   │
│                                     │
│  ★ 取消检测：每 0.5 秒检查一次       │
└─────────────────────────────────────┘
    ↓
[隐私还原] → PrivacyEngine.deanonymize()
    ↓
[持久化] → 保存完整工具调用链
    ↓
输出给用户
```

## 📝 配置文件

### global_config.json

```json
{
  "model": "qwen3.5:4b",
  "privacy": true,
  "dark_mode": false,
  "topmost": false,
  "thinking_depth": 3,
  "permission": "ask",
  "custom_models": {}
}
```

| 字段 | 说明 |
|------|------|
| `model` | 当前使用的模型名称 |
| `privacy` | 是否启用隐私脱敏 |
| `dark_mode` | 是否启用暗色主题 |
| `topmost` | 是否始终置顶（**默认关闭**：常驻最上层会挡住别的窗口；要置顶在设置页/顶栏图钉一键开，值会持久化） |
| `thinking_depth` | 思考强度（1–10，界面按四档显示：低2 / 中4 / 高7 / 最高10） |
| `permission` | **新对话默认**权限档位（`plan` 计划 / `ask` 变更前确认（默认）/ `auto` 自主 / `full` 完全访问；旧中文档位名自动兼容）。每个对话可在输入区胶囊里单独覆盖，覆盖值随会话存在 `chat_sessions.json` |
| `custom_models` | 自定义外部模型配置 |
